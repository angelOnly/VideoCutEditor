# 两阶段耗时优化开发说明

对应《VideoCutEditor 两阶段耗时优化实施方案 v3》，开发日期：2026-10-12。

## 已实现的流程

Analysis 与网页确认保持原协议。一个 Render 连贯完成设计、配音校准、实现、正式分镜、审片和交付，不再提交代表段样片作为正式批次门槛。环境能力预检保留。

主要调用链：

```text
finance_timeline.derive_timeline
  → 正式执行时间轴投影为本镜 props 与必要全局上下文
render_batch.freeze_batch
  → production_contract.validate_production_inputs
  → 音频覆盖检查及独立只读进程中的完整模板参数检查
  → review-plan.json、输入指纹、不可变批次
render_batch.render_batch
  → 重验当前输入 → 按构建输入复用 bundle
  → stage_media.render_scene → 内容键复用或真实生成
  → 按当前视频摘要准备审片图片
Render 实际观察 → review.json 与交付 manifest
 task_io.complete_render
  → 创建本次 ValidationContext
  → assemble（缺少整片时）→ two_stage.validate
  → 核对完整媒体、当前设计和证据 → 既有 Worker 结果接口
```

## 新财经模板的输入合同

工具与插件版本为 1.5.0；财经模板的 renderer-manifest.json 与发布 ZIP 同步为 1.5.0。

新任务必须明确 `timeline.renderInputContract = "finance-scene/v2"`，工程带 `render-contract.json`。独立 `design.json` 使用 `schemaVersion: 2`，通过 `scenes.<sceneId>.designs` 保存设计 ID、口播引用、模式、说明及实现位置。变化设计的 `eventRefs` 引用实际使用的 visualBlocks；动作检查位置来自组件入场、itemFrames、revealFrame 和 animationFrames 的执行边界。扩展组件须声明并实际消费自己的 animationFrames。

`derive-timeline` 不再写 `src/timeline.ts`；分镜统一选择 `FinanceScene` Composition。保留全片进度、章节导航、BGM、正文保持所需数据，其余镜头局部内容不进入本镜 props。未知顶层或分镜执行字段直接拒绝，不静默丢弃。

新合同通过 macOS seatbelt / Linux Landlock 隐藏任务记录，构建和渲染在任务目录内仅能读取当前工程及执行目录；按用户确认，不额外限制网络，沿用 Worker 原有网络权限。原生模式不能启用记录排除。完整时间轴校验在单独的只读进程完成，临时输入随后移除，不暴露给构建进程。

旧任务不自动迁移。没有声明新合同的模板显示 `legacy-conservative`，仍按完整输入保守失效。明确迁移须同时调整工程入口、记录位置与执行参数，不能通过修改 marker 或摘要冒充新合同。

## 复用与审片

- `currentBatchVersion` 负责当前批次归属，`renderInputKey` 负责媒体内容。缓存 schema 升级为 2，同任务、同 run 内复用，不提供跨用户共享缓存。
- 键覆盖工程与 public 内容、共享组件、依赖、浏览器、工具、真实 props、音频合同、帧数及输出规格；公共源码和资源变化保守失效。
- 返回 `cacheHit`、`cacheMissReason`、`cachedFrom`、`browserRenderCount`、`newRenderedFrames`，不能仅凭 MP4 摘要相同判断是否节省了生成。
- 原画面与 PCM 恢复机制保留；最终 MP4 损坏不会被直接复用。证据失败不会转成浏览器重渲染。
- `review-plan.json` 仅列待检查项，不含 observed、viewedFrames 或 passed。正式视频按摘要分目录存图，FFmpeg 一次精确选取多个帧；相同媒体只补缺图或被修改的图片。
- review 绑定当前 `timelineSha256`、`designSha256` 和视频摘要；设计预期变化必须重新核对作品。自动提图不等于实际观察，也不证明连续播放或试听。
- 增加观察位置可调用 `stage_media.py evidence`，再将返回的真实 evidence 加入当前清单。变化设计的终检与生成工具共用动作窗口及所需帧规则。

## 交付与失败处理

Worker 正常路径只显式调用 `task_io.py render`。底层 assemble 和 validate 仍可用于诊断。

ValidationContext 只保存本次进程产生的技术事实，按真实文件摘要、预期规格、参数及检查器身份复用；不读取任务自行填写的通过标记。图像真实性比较和整片拼接边界取帧按视频聚合。普通音频元数据不扫描视频帧数；严格 MP4 和片尾检查仍实测帧数并验证解码。整片顺序、总长、声音拼接、资源授权及当前设计对应关系不省略。关键边界再次核对文件内容。

结构可解析时，设计缺漏、字幕越界等独立问题一次返回 `VISUAL_REVIEW_REQUIRED`，并携带 category、issues、文件和字段位置。JSON 或基本结构损坏优先报根错误。修复预算、连续无进展保护、取消、租约与进程回收沿用原机制，不豁免反复失败。更新了一个仍要求旧 budgetOwner 策略豁免失败的过期测试，使其验证当前预算不可被任务文件关闭。

## 性能观测与运行配置

新增输入核验、指纹、浏览器启动、Composition 选择、实际渲染和编码耗时；保留既有封装、取证、批次墙钟等指标。批次记录实际新渲染次数、帧数和统一 cgroup 资源快照，包括 CPU、节流、内存事件及 I/O；各镜看到的同一 cgroup 数据不能相加。

Worker 的 `RENDER_FRAME_CONCURRENCY` 只接受 1 或 2，默认 1，注入任务为 `VIDEOCUT_FRAME_CONCURRENCY`。与分镜槽位共同受部署配置约束。没有新增可由模型随意提高资源上限的命令参数。

既有 `render-benchmark-adapter.py --generate` 增加 `--frame-matrix`，生成 5×1、3×2、4×2、5×2 对照，每组沿用至少三次、固定输入和隔离输出规则。新合同的 18 镜源工程需带正式 design.json、timeline.json、实际音频、工程及派生 props。基准不构造人工通过记录，也不成为生产任务的前置样片。

## 本地验证及边界

新增 `test_production_optimization.py`，使用真实 Remotion 4.0.425、Chrome 和本地合成音轨验证：首次两镜生成、补设计说明零新增渲染、独立标签修改仅一镜失效、最终 MP4 损坏时复用原画面与 PCM、只补缺图、统一交付内技术检查复用、设计变更及图片损坏阻止旧结论交付。另覆盖多问题汇总、真实动作窗口、全局依赖失效、未知字段和读取隔离。

真实浏览器回归通过 `RUN_OPTIMIZATION_BROWSER=1` 与 `TEST_NODE` 启用；可用 `TEST_BROWSER` 指定浏览器。媒体测试需要带 libx264 的 FFmpeg，本地通过 FFMPEG / FFPROBE 显式选用对应版本，不修改系统安装。

本地全量 Python 回归共 172 项：169 项通过、3 项按环境条件跳过；Worker 相关回归、TypeScript 检查、模板参数与类型检查通过；基准工具的 17 项回归通过。最后的 6 项优化专项回归通过，含真实浏览器、真实音轨及同次交付每镜只做一次取帧解码的计数断言。模板 ZIP 已逐文件核对，插件发布摘要与源码一致。

初版代码验收时尚未连接服务器，也没有执行历史 18 镜工程的质量对照或并发性能矩阵；后续服务器兼容修复与验证见下文。现有回归不能用于宣称生产耗时已降至某个数值，仍须用同一实际源工程执行并发性能矩阵。

明确保留的代价：首次升级冷缓存；共享源码和 public 资源变化可能使全批失效；旧模板维持保守模式；检查事实不跨进程复用；取消强制样片后，部分运动问题可能在正式作品中发现并修订。

## 2026-10-12 服务器兼容修复（插件 1.5.1）

真实网页任务的 Analysis 已通过；首轮 Render 在 freeze-batch 被嵌套 bwrap 命名空间限制拒绝，尚未启动正式视频渲染。按用户确认，Linux 改用 Landlock ABI 3+ 限制渲染文件访问，不额外限制网络，沿用 Worker 原有网络权限。macOS 仍使用文件沙箱，也取消新增的外网限制。联网权限不意味着远程资源可作为隐式缓存依赖：制作素材仍应先下载到固定本地输入。

`render_inputs.isolated_command` → `render_landlock.py` → Node 构建／参数核验／浏览器渲染。任务记录不可读，工程及打包结果只读，当前执行临时目录可写；限制由内核继承给子进程，不能扩大 Codex 外层权限。旧工程继续采用保守缓存身份。Landlock 不可用时明确失败，不回退为无限制执行。代价是要求 Linux 内核支持 Landlock ABI 3+；不另建渲染代理服务。

新增 Linux 实测覆盖文件、软链接、写入、子进程继承和网络保留，并把分镜文件读取隔离纳入 `host:check` 的真实 Codex 外层沙箱检查。

## 2026-10-12 批量入口修复（插件 1.5.2）

服务器复测中，Landlock 冻结输入成功，但 `render_batch.py` 的批量入口仍只接受旧隔离方式，因此在实际浏览器启动前失败。已补齐入口允许值，并增加批量入口回归；渲染工具指纹包含隔离包装器，避免包装器改变后误复用旧产物。

服务器真实浏览器专项回归共 6 项，5 项通过、1 项 macOS 专项跳过，实际覆盖视频生成、设计说明修改不重渲染、单镜修改、损坏成片恢复和交付技术校验复用。Linux 文件隔离及网络保留实测、真实 Codex 外层沙箱下的 `host:check` 均通过；本地批次回归 21 项全部通过，Worker 相关回归 7 项及类型检查通过。
