# 主控节奏与章节并行测试报告

本报告随实际验收更新；未完成的媒体与性能项不标通过。独立工作树基于 `c68f7d0`，不推送、不合并、不部署，未修改原工作区、根 `.env`、生产队列或原进程。

## 已实现与验证

- `freeze-batch` / `render-batch`：冻结工程、时间轴、props、运行时依赖；只读共享 bundle；按长镜头优先分配 1/2/3 槽，输出按确认顺序；独立分镜结果、失败恢复、统一墙钟预算和取消。
- `video_chapters`：真实 app-server 章节会话，主控先给 direction/brief；文件代理限制章节写入范围，不开放进程、收费配音和最终交付。候选绑定确认稿、编排正文、brief、真实音频锚点及文件摘要，主控仍须审查并合并。
- 宿主和本地驱动复用核心；宿主全部受控媒体操作共用 FIFO 槽。默认仍为 1，性能证据满足要求后才决定是否推荐 2；3 仅用于实测。
- 进度登记携带渲染时 `timelineHash`，拒绝旧版和缺失摘要；同一 registry 以队列串行更新，32 路登记不丢记录。

## 真实章节创作

独立 app-server 使用 `0.155.0-alpha.9.2`、`gpt-6-astra`、`medium`，三个真实会话并行启动并写出候选。正式 Worker 锁定的 `0.154.0`、Linux cgroup 尚未实测，不能据此宣称部署链路全自动验收通过。

第一轮主控退回第一章：前 372 帧图解区空白、部分卡片复述长口播。修改 brief 后，旧候选实际被拒收；第二、三章保留。第一章第二次派发修正草案。主控继续减少第二章份额骤降后的重复入场，并修正同句多项动画的节奏。子代理约定的句级锚点仍与 57 段原音频对应；12 帧分层动效是设计节奏，不声称词级对齐。

整片代码审查发现旧片尾会覆盖整段收束镜头。仅在新任务工程增加片尾局部起点：先停留结论，末尾再进入原品牌动画。总帧数暂保持 4112，必须以实际混音和解码复核。

章节原始执行、文件摘要、过期拒收和主控草案审查见本目录 `章节执行/`。真实文件代理权限负测使用真实磁盘、模拟 RPC，已明确区分，不当成真实 app-server/Linux 权限攻击验收。

## 资源隔离与等待

独立任务 `projects/render-parallel-20260923` 只复制必要输入和 57 段配音，没有复制旧成功账本或成片。依赖只读复用；不新增收费 TTS。

原工作区遗留三组孤立 Chrome。对完整 21 个进程只读观察约 62 秒，最高 CPU 0.1%，约 1 GiB 常驻 RSS；不杀原进程。只有绑定 PID/启动时间及原始采样摘要的持续闲置进程可列作外部基线，CPU 超过 1% 或出现未知媒体后代即阻挡。此环境不是完全独占机器，外部 RSS 单列。

预览期间原 `finance-ai-chip-20260923` 测试恢复真实渲染，守卫中断了己方预览。此次 12.49 秒中断属于资源争用，不纳入性能统计。后续渲染等待原测试空闲。
