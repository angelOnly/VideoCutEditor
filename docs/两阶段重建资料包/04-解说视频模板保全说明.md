## 2. 必须保留的视觉改进

- 发言者小圆头像 130×130，待场头像 64×64；不回到大半身像占据画面的布局。
- 观点卡与完整字幕分开，中央数据面板是视觉主体。
- 短句字幕分页与安全区，不能整段长句铺满屏幕；当前模板每条最多 28 字。
- 深色面板、红青配色、数字/图解递进、入场与退场、章节转场。
- 底部章节摘要、小标题导航、当前章节高亮、全片红色进度条；跨 sceneId 不归零。
- 双主持按角色发言，模板图片/声音安排保持一致；角色音色授权在新环境核对，不把所有角色替换成一个音色。
- 片头片尾和数据组件复用，允许为新稿件创作专属图解，不照搬历史节目数据。

参考片位于模板内 assets/video/reference/financial-report-dialogue-v3-final-cut-preview.mp4。说明中指出，参考片底部短句是章节摘要，当前模板另留字幕带，这是已明确的布局适配。
这些要求归属本模板，不是所有视频的全局硬规则。

## 3. 外部依赖与移交边界

模板声明 Remotion 4.0.425、React/React DOM ^18.2.0，开发类型/TypeScript 版本见 package.json。本包不含 node_modules、Node、FFmpeg、Chrome 或账户凭据，不能当作开箱即跑的离线运行环境。
说明中引用 examples/hello-world 的历史源码/成片用于来源说明；本包保存的是当前可复用 renderer 和包内参考资源，不保证包外路径跟随迁移。
当前模板的时间轴字段、句级审计和校验脚本属于模板实现快照。先保全，再按新基线适配；不能为通过测试直接删除模板审美要求或绕过校验。

## 4. 模板验收门槛

恢复后先用少量本地测试配音做短片，查看男女切换、最长字幕、数据逐步出现、章节前后、跨句进度条和片尾。
然后使用新稿件验证同一风格仍成立，最后再测试黄仁勋完整稿。静态图或类型检查不代替动态片段与声音检查。
本轮未运行上述测试，未修改模板及原 ZIP。

## 5. 接入开发时具体使用哪些文件

```text
Worker 获取/读取已准入模板 → 冻结本任务副本
  Analysis → 只取模板的“文本分镜说明”
  Render   → 主说明 + 动效说明 + renderer 清单 + 源码 + 参考片/素材
            → 在任务 project/renderer 填写本期内容与实际时间
            → 整体审片 → 按确认列表导出分镜 → 交付校验
```

| 文件 | 用途与接入规则 |
| --- | --- |
| 财经双人对话视频生成指令.md | 栏目总要求；Analysis 只读文字拆分相关部分，Render 读完整制作要求 |
| 动效组件与内容适配说明.md | 新稿件如何选择图解、安排逐步出现和转场，不把历史财报数字当新稿件内容 |
| renderer/renderer-manifest.json | 入口、Composition、时间轴模块、校验器和依赖约定 |
| renderer/src/index.ts、Root.tsx | Remotion 入口及整片/分镜注册 |
| renderer/src/timeline.ts、types.ts、timeline.example.json | 本期内容结构和模板适配格式；示例不是新稿的实际时长 |
| SpeakerStage.tsx、SubtitleLayer.tsx | 主持切换、小头像、字幕呈现；不能用新写的大人物布局替代 |
| VisualBlocks.tsx、ChapterTransition.tsx | 图解组件和章节切换；允许在本任务内补充必要图解 |
| ChapterNav.tsx、FinancialDialogue.tsx | 全局章节、进度及主布局；分镜也必须保留全局时间上下文 |
| FinancialIntros.tsx | 复用片头片尾，不给每个外部分镜重复插片头 |
| validateTimeline.ts、scripts/verify-sentence-audio.mjs | 模板内格式及句级音频检查，不升级为所有模板的通用限制 |
| assets | 图片、音效、参考视频等；复制后按清单映射到 public/template-assets |

清单声明整片 Composition 为 FinanceEpisode；分镜为 FinanceScene- 加从 1 开始的序号。外部 sceneId 仍保持确认列表的 ID，不直接当 Composition 名称；必须保存两者映射。

## 6. 时间轴适配不能再丢信息

Render 先依据实际配音与素材安排制作时间，再转成模板需要的字段。转换仅负责格式与单位，不重新用字数估时、不自行缩短镜头、不丢掉字幕、章节或音频来源。
如果既保留 render/<runId>/timeline.json 又生成模板 timeline.ts，必须来自同一份本期制作决定，并验证镜头顺序、帧数、字幕、音频和章节一致。不能让两个脚本分别决定时长后互相覆盖。
模板原有句级短音频策略继续作为此模板的现状保留；已有效的句级音频优先复用，不能为了更新画面重新收费配音。底层导出适配要先测兼容性，不能假定旧整片工具可不改直接用于分镜。

## 7. 开发后的具体审片清单

| 检查片段 | 看什么 | 不通过时修改哪里 |
| --- | --- | --- |
| 男女轮流发言 | 小头像、高亮、角色声音一致，观点卡不塞全文 | 本任务角色映射/模板使用方式 |
| 数字密集与非数字叙述 | 图形随语义递进，不把所有稿件都做同一张卡 | 本任务 visualBlocks 与时序 |
| 最长字幕 | 分句、同步、安全区、可读字号 | 本任务字幕数据；模板自身错误另报人工 |
| 章节交界与相邻分镜 | 小标题正确、导航连续、进度不归零、无重复片头 | 本任务全局偏移与导出映射 |
| 末句与片尾 | 口播完整、无意外尾音、画面结束合理 | 本任务声音和画面安排 |
| 最终 MP4 | 与工程预览一致，无黑帧、裁切、颜色异常或失步 | 先定位工程还是共享导出问题 |

先做短样覆盖上述情况，再跑完整黄仁勋稿及另一份不同主题稿。交付审片证据至少包含参考与成片对应截图、真实动态片段、实际时长、字幕及音频完整性结果；类型检查和静帧不能证明动效节奏合格。
