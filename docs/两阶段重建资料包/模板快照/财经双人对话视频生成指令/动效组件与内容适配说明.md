# 财经双人模板：动效组件与内容适配说明

适用版本：1.1.0。此文与 `renderer/` 一起使用，不是让模型重新设计一套动画的提示词。

## 来源与固定边界

视觉来源为模板内 `assets/video/reference/financial-report-dialogue-v3-final-cut-preview.mp4`，原始实现为项目 `examples/hello-world/src/FinancialReportDialogueV3.tsx`。本模板保留其小圆头像、观点卡、深色中央面板、红青配色、分批入场、章节摘要、章节导航和红色全片进度。原片财报数据和历史配音不复用。

参考片底部短句是章节摘要，不是完整字幕。为了保留本模板要求的逐句字幕，中央面板底边从距底 150 调整为 190 像素，单独留出字幕带；这是一项明确的布局适配，不应放大人物补空白。

| 区域 | 1920×1080 的固定规则 |
| --- | --- |
| 发言者 | 左／右距边 52，顶部 124，130×130 圆头像；观点卡宽 540 |
| 待场者 | 另一侧距边 58，顶部 150，64×64 圆头像，透明度 0.3 |
| 人物观点 | `scene.summary`，建议 8–18 字，最多 22 字；不是原文字幕 |
| 数据面板 | 左右 58、顶部 280、距底 190；标题最多 32 字 |
| 逐句字幕 | 距底 128、高 48、字号 30；每条最多 28 字，建议 12–24 字 |
| 章节摘要 | `chapter.summary`，最多 40 字，独立于字幕显示 |
| 章节小标题 | `chapter.label`，最多 8 字；1–6 章，当前章节高亮 |
| 播放进度 | 距底 20、高 4，按全片绝对帧推进，不能每句归零 |

人物、配色、字体、面板、导航和现有动效实现不随稿件改写。长内容必须拆分或提炼，不能缩小字体、裁切或隐藏。若现有组件确实无法表达，先明确缺失类型；仅扩展中央面板组件并补校验和测试，不重写视觉骨架，不伪称与参考完全一致。

## 两阶段与时间坐标

Analysis 仍仅切分、确认原稿，不制作媒体。Render 同时读取原稿、已确认 `sceneId/content` 和当前冻结模板，在内部完成以下适配；不改变接口和已确认文本。

1. 按语义归并逻辑章节，提炼章节标题、摘要和各分镜观点。章节不等于分镜，通常跨多句。
2. 在每个确认分镜内部，把长句按语义停顿拆为独立短句 TTS；保留文字、标点、顺序，避免拆开专有名词和数字单位。
3. 使用真实音频时长生成 `utterances/captions`，二者一一对应。短句拼接必须等于确认分镜，不允许配音改写成问答。代价是 TTS 请求变多，需试听衔接自然度。
4. 先选下表动效类型，再填写数据。触发点优先绑定短句开始；需要精确表现句中信息时，应在制作配音前合理拆短句，不按字数推测时间。
5. `scene.from`、`chapter.from/endFrameExclusive` 是全片帧；`utterances/captions`、场景图解是分镜内帧；章节 `visualBlocks` 是章节内帧；`props.itemFrames/revealFrame` 是组件内偏移。
6. 默认将图解放入 `chapters[].visualBlocks`，`scene.visualBlocks` 留空。只有确需单镜专用面板时才填写后者；它会替换该镜的章节图解，不是叠加。
7. 单镜导出也必须传入完整 `timeline`。章节动画时间是 `scene.from + 当前帧 - chapter.from`，导出多条 MP4 后拼接与全片视觉一致。

单镜 Composition 名为 `FinanceScene-1`、`FinanceScene-2` 等，按 timeline.scenes 顺序映射原 sceneId；避免把下划线等非法字符带入 Remotion 名称。交付文件与结果仍使用已确认 sceneId。

触发帧示例：一条音频在全片第 420 帧开始，章节从 300 开始，组件从章节内 30 开始，那么对应的 `itemFrames` 是 `420 - 300 - 30 = 90`。这只是坐标换算，不是时长估算。

所有组件的入场使用 13 帧三次缓出、向上 20 像素，随后保持直到 `endFrameExclusive`。章节标题独占无对白的转场空档；标题退出后人物入场。不能每切一句就清空章节面板。片尾隐藏正文 UI，收束配音继续，动效 67 帧后保持末帧，配音结束立即结束。

## 动效组件配方

共同字段：`id/kind/startFrame/endFrameExclusive/slot/props`。`slot` 可为 `full/top/bottom/left/right`；默认 full。同时存在的组件必须占不相交区域，禁止相互覆盖。先预留区域再逐项出现，不能让已显示内容跳位置。trend、line 使用 full/top/bottom；ring 使用 full/left/right；labels 在 top/bottom 最多 4 项。

| kind | 用途与必填 props | 入场与容量 |
| --- | --- | --- |
| metric | 单项指标：`label/value/detail`，均为字符串 | 标签≤24 字、值≤12 字、解释≤28 字；指标卡淡入上移，不伪造计数过程 |
| comparison | 两方对比：`items`、`itemFrames` | 恰好两项，各≤18 字；左右卡按绑定帧依次出现，红青／金强调 |
| layers | 模型层级：`items`、`itemFrames` | 2–5 层，各≤22 字，只用 full；逐层错位入场 |
| flow | 因果或时间步骤：`items`、`itemFrames` | 2–4 项，各≤18 字；编号、箭头和节点分批出现 |
| labels | 验证点、观点清单：`items`、`itemFrames` | 2–5 项，各≤18 字；两列卡片、勾选标记、逐项入场 |
| quote | 核心观点：`label/text` | 标签≤24 字、正文≤40 字；红色强调边，不能放整段旁白 |
| trend | 仅有前后端点：`label/from/to/revealFrame` | 两端值均为≤12 字的字符串；连接条填充 28 帧、终点显现，不编造中间折线 |
| line | 有真实序列：`label/values/labels/source/revealFrame`，可选 `unit` | 2–6 个有限数值、等量短标签≤8 字；SVG 折线用 strokeDashoffset 在 45 帧内绘出；source 记录稿件依据 |
| gauge | 百分比与阈值：`label/value/threshold/detail/revealFrame` | 数值均为 0–100；进度条填充 26 帧，阈值虚线保留 |
| ring | 占比：`label/value/detail/revealFrame` | value 为 0–100；环形扇区展开 26 帧，中心展示目标百分比 |

`itemFrames` 必须与 items 等长、严格递增，并为最后一项留足 13 帧入场时间。`revealFrame` 必须是非负整数，组件至少再保留 46 帧供动画完成。先出现外框与标签，再在对应配音触发点展开主体。以上持续时间只控制视觉入场，不决定配音时长。

没有数字的观点稿使用 comparison、flow、layers、labels 或 quote。不能为了“丰富”凭空生成百分比、阈值、时间序列。只有两个数值端点时用 trend，不用 line。信息过多时按语义拆为顺序展示的多个组件，不在一个面板内无限堆卡。

例如 AI 产业稿：“五层模型”选 layers；“两地应用差异”选 comparison；“市场份额从近 90% 到 0”选 trend；政策影响链选 flow。财报稿可选 metric + line 或 gauge + ring；没有数据的评论稿不强制出现数字图表。

## 最小数据结构

`renderer/timeline.example.json` 是字段示例，不是真实任务配音，也不能直接交付。Render 必须生成本期真实音频、`src/timeline.ts` 及任务内部 timeline.json。

章节对象包含：`id/label/title/summary/from/endFrameExclusive/visualBlocks`。保留已有场景字段。`scene.chapter` 只表示该分镜开头的标题转场，不能代替顶层 chapters。本地渲染数据结构升级不改变 Worker 外部协议。

## 验收与失败处理

1. 运行 manifest 中 `sentenceAudioValidator`：校验原文拼接、独立音频真实时长、字幕文字和边界。不接入新的付费对齐服务。
2. Remotion Root 自动运行 `validateTimeline`：缺章节、超长文字、非法帧、图解重叠、错误参数直接失败。修正当前数据；禁止跳过校验、吞字段或退化成静态长文本。
3. 抽查正文男女切换、最长观点、最长字幕、章节前后、跨 sceneId 的同一图解、底部导航和片尾。对照参考片检查小头像比例、信息层级、红青色及留白。
4. 动效不能只看最终静帧：至少导出入场前／中／后三帧并播放短片，确认卡片依次出现、线条或条形确实变化。
5. 技术校验不能证明语义正确或完全还原参考。核对数字与来源、试听短句衔接、检查字幕不溢出；失败时报告具体镜头和原因，不能宣称可交付。

维护模板时运行项目 `tests/test_sentence_audio_validator.mjs` 和 `tests/test_finance_template.cjs`；后者可加 `--render` 生成无付费 TTS 的视觉回归样片。这些是开发测试，不交由 Worker 执行任意新脚本。

发布时同时更新模板目录和同名 ZIP。既有任务的冻结模板不会自动改变；必须使用新包创建新任务，不能覆盖旧任务快照。旧任务缺 chapters 或含长字幕时需重新制作数据，不能静默迁移后假定视觉合格。
