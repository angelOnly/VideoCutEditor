# Render 导演与美术动效 Skill 接入最终方案

日期：2026-10-09。状态：导演、美术 Skill 与插件接入已按本方案完成本地开发；服务器部署及实际成片验收另行记录。方案中的“拟修改”保留为实施依据，不代表已经通过效果验收。

## 1. 先看这一页：本轮到底做什么

本轮只做三件事：

1. **通过制作插件接入两份创作 Skill。** 将完整 Skill 打包、安装到服务器，由 Worker 在 Render 开始时明确启用。Render 先使用 `directing-motion-art` 把文稿写成能被想象的连续演出，再使用 `motion-design-production` 深化主体、美术、构图和运动，并实现本期组件。
2. **由各模板声明自己的创作边界。** Render 下载并冻结模板后读取；通用 Skill 只负责遵守，不内置头像、导航或中央面板等保护清单。案例帮助选择表现方法，技术文档帮助实现。删除旧文档中重复的一般设计指导，避免多份规则互相覆盖。
3. **预览时按问题返修。** 没有视觉事件就改导演方案；造型和构图差就改美术；中途混乱就改运动；设计未实现就修代码。保留已有音画同步和交付检查。

网页仍然是“数据解读 → 选择定制化模板 → Analysis → 确认 → Render → 交付”。导演、美术和动画是同一个 Render 内部的工作步骤，不新增业务阶段、服务、Agent 或用户审批环节。

当前 analysis、render、配音、渲染和合片都在服务器 `10.20.130.251` 运行。已部署的是 `videocut-production 1.0.1`，包含原有制作能力，尚未接入这两份新 Skill。插件化解决能力的安装与调用；动画效果仍要靠本方案中的设计、实现和预览返修改善。部署证据见 [Codex 制作插件部署与验收记录](Codex制作插件部署与验收记录.md)。

本次修订保留导演、美术和动态模板边界方案，调整第 8、9、11 节的接入与部署方法：从“开放仓库里的 Skill 目录”改为“发布新版插件并明确启用其中的 Skill”。插件与模板分别发布，不把模板装进插件。

**一句话说明：先把这一段怎样演讲清楚，再把这场演出画好、动好；全部发生在当前模板允许的正文区域内。**

阅读建议：第 2—7 节说明原因和新流程，第 8—10 节是开发落点与拟写入文本，第 11—12 节说明验收和代价。附录保存按本次要求去除教学案例后的两份 Skill 待接入文本，可展开阅读。

## 2. 为什么前两轮还没有解决画面效果

### 2.1 已经解决和需要保留的部分

插件迁移前的任务 `dc89d57a-3c2c-484a-ac6b-8abe7ba1f75b` 已生成整片。用户观看后确认：声音讲到哪里，对应动画会在那个时候展示。

因此，本轮保留真实配音时间轴、对象的语义时间对应、已有 `narrationChecks`、成片证据核对，以及正文结束后的片尾流程。用户认可同步改善，不等于所有时机和视觉质量已经完成独立验收。

此前的开发记录保留了当时的“未部署”状态；随后已推送并部署 `c3bb796`，经正常网页完成新任务并下载成片。本方案记录后续用户反馈，不把历史开发记录的状态误当作当前状态。

随后服务器插件 1.0.1 的任务 `a5981280-d939-40af-b418-04b609819fbb` 完成了正常网页两阶段测试，已核验实际插件加载与成片输出。正文仍偏文字卡，不能把插件迁移成功当作动效优化已经完成。

该次测试还发现固定结束语漏播：正文结束后才播放片尾，但 `ending.closingUtteranceIds` 为空，音频未包含模板的固定结束语。这是待修问题，不是已通过的片尾验收项；现有证据也不足以认定它由插件迁移引入。后续须独立核对并修复，不能指望导演、美术 Skill 顺带解决，验收要求见第 11.4 节。

### 2.2 当前仍然存在的问题

用户提供的截图中，正文主要表现为：结论文字卡、左右文字列表、等宽层级文字条、带箭头符号的文字框。它们可以按口播依次出现，却仍要求观众通过读字理解内容。

问题需要分开看：

| 层面 | 当前反馈或已知限制 | 本轮处理 |
| --- | --- | --- |
| 时机 | 用户确认同步已经改善 | 保留已有实现 |
| 表达 | 主体仍常用文字替代过程 | 用导演 Skill 明确可见事件和观看顺序 |
| 美术 | 文字卡即使换成图形，也不自动好看 | 用美术动效 Skill 深化轮廓、比例、空间、材质和排印 |
| 运动 | 按时出现不等于完整演出 | 设计动作发起、跟随、交叠、危险中途和出口 |
| 审阅 | 字段、时间与证据有效不能证明吸引力 | 实际看图和过程，按问题所在环节返修 |

“数量用图表、结构用层级、因果用连接”只能作为理解内容的起点。它没有决定具体主体、观察距离、发现顺序与动作性格，不能作为完整创作指令。

### 2.3 旧方案、新方案与删除项

旧方案依赖一般创作提醒、组件实现和同步检查，容易退回“选一个布局、填文字、按时入场”。新方案把完整导演演出与美术运动深化放在组件选择之前。

拟替换 `production-flow.md` 中目前较简略的正文创作步骤；把 `motion-design.md` 中重复的通用设计指导迁移为对新 Skill 的引用。保留该文件中的项目时间、坐标、组件接入和片尾约束。

不删除现有基础组件：短引语、标题、结论等仍可适当使用。删除的是“默认从组件菜单出发”的制作倾向和重复指令，不是禁止文字或强制每句话都画图。

## 3. 模板边界由模板自己控制

### 3.1 三层职责

| 层次 | 负责什么 |
| --- | --- |
| 模板包 | 声明本模板必须保留、允许创作、允许更新的内容，以及实际接入位置 |
| 当前任务要求 | 确认本期内容与用户明确指定的额外约束；明确覆盖模板默认项的用户要求按本次授权执行 |
| 通用导演、美术及流程 Skill | 读取并遵守当前任务边界，设计和实现；不内置具体栏目的保护清单 |

不同模板可以有完全不同的创作范围：财经模板可以只开放中央图解；产品模板可以保留 Logo 和字体、其余全屏创作；图表模板可以只固定数据尺度和标注规则。没有头像的模板不要求加头像，没有中央面板的模板不创建中央面板。

“正文创作层”在本文中指当前模板允许创作的部分，不表示所有模板都存在固定尺寸的正文容器。参考片出现某个元素，也不自动表示该元素必须保留。

### 3.2 最简单的声明方式：复用已有说明入口

不新增服务、MCP 或强制 JSON 边界协议。边界正文用 Markdown 写在模板说明中；说明较长时可拆成文件，由现有模板说明或清单引用。

当前财经模板已经有 `renderer/renderer-manifest.json` 的 `motionGuide`，指向 `../动效组件与内容适配说明.md`。直接在这份说明里集中维护“创作范围与保护边界”，主模板文档及清单只引用，不再各写一套清单。

其他模板可以使用自己的说明入口，不要求必须提供 `motionGuide`、`renderer-manifest.json` 或相同文件名。将来确有统一机器校验需要时再设计结构化协议，本轮不提前增加。

模板声明需说清五件事：

1. **必须保留什么：** 保护的是组件、外观、位置、比例、行为还是文字内容，避免只写“保留风格”。
2. **允许创作什么：** 可用区域、可改变的构图、主体、局部材料与运动。
3. **允许按任务更新什么：** 如章节名称、人物观点、数据、字幕，不能误当成锁定文案。
4. **实际怎样接入：** 对应组件、资源、可用区域的代码来源及时间坐标约定。
5. **哪些只是参考：** 示例内容、案例布局、演出和时长，不作为每期固定要求。

### 3.3 Render 下载后怎样读取

```text
选择模板 → 现有下载与冻结流程
→ 读取冻结包的主说明及清单
→ 有创作范围说明引用时，按引用读取包内文件
→ 对照实际工程确认受保护元素、可编辑位置和入口
→ 结合当前任务要求，在 direction 中记录有效边界及其来源
→ 导演设计 → 美术运动实现 → 按当前模板边界预览检查
```

相对路径从声明所在文件解析；例如财经 motionGuide 相对于 renderer 清单，解析后仍在模板根目录内。只读取本任务包内实际文件，不跨到其他任务或历史模板。模板说明提供创作约束，不授予执行任意模板脚本的权限。

旧模板未单列边界章节时，读取现有主说明、清单中的规则和实际工程继续制作，不因缺少新文件就报错，也不要求所有旧模板重新打包。声明引用文件却不存在或与源码不符时，先核实其他有效说明；只有实质冲突无法判断、会影响主要设计时才澄清。没有声明保护全部画面时，不能把整张参考画面自动锁死。

当前任务使用冻结版本，不在制作途中读取网页后来替换的新包。换模板或创建新任务时重新读取，不能复用上一模板的保护清单。

### 3.4 仅当前财经模板的边界示例

下面的规则应写在财经模板包里，**不写进通用 Skill**；具体拟写入文本见第 8.1 节。

| 内容 | 财经模板自己的约束 |
| --- | --- |
| 人物头像、人物位置、说话人状态、人物观点卡 | 保留栏目组件、位置关系、头像比例与状态表现；观点文案和说话状态按本期更新 |
| 底部主题导航、进度条 | 保留样式、区域与运行方式；章节标题和数量按本期编排 |
| 字幕、Logo、栏目背景 | 保留规则与视觉身份，正文不能遮挡；字幕文字与时间来自本期确认口播 |
| 片头、固定结束语、片尾 | 按模板与任务实际选用情况处理，沿用已确认的完整声音与播放顺序 |
| 中央正文图解 | 可重新设计主体、内部布局、场景、局部材质、标签与连续运动 |
| 原参考片正文和基础图解 | 是参考或可选实现，不锁定本期对象、数据、演出、层数或组件种类 |

新 Skill 中改变背景、取消标题等建议，只有在当前模板和任务允许的区域内才适用。在这个财经模板里，它们不能用于删除人物和底部导航；在允许全屏重构的另一模板中，则可以采用不同的画面组织。

## 5. 新的 Render 制作流程

```text
正常网页提交 → Analysis → 确认文稿 → Render
                                      │
                                      ├─ 校验服务器已安装插件，明确启用制作、导演、美术 Skill
                                      ├─ 读取本任务模板与完整内容，明确保护边界
                                      ├─ 导演 Skill：写完整观看过程
                                      ├─ 美术动效 Skill：深化主体与关键画面
                                      ├─ 实际配音：校准声音接点与动作窗口
                                      ├─ 本期组件：实现连续演出
                                      ├─ 在完整模板里预览，按问题返修
                                      └─ 批量渲染、成片审查、原有交付
```

流程表达依赖关系，不要求所有工作机械串行等待。设计草案可以在配音前形成，已有有效音频可以直接使用；最终动作以真实配音为依据。

### 5.1 导演：从文稿形成完整演出

先理解整片，再组织主要视觉段落。段落由观看需要决定，不要求跟随每个句号；交付 ID、数量和顺序仍服从确认列表。

每段形成连贯指令，讲清：本段作用，主要对象与观察方式，第一关注，美术方向，入口与出口，动作发起与跟随，危险中途，准确上屏文字，声音接点，以及需要先试作的过程。

导演锁定影响事实、主要表达、栏目要求和前后衔接的决定。精确坐标、色值、曲线及细部造型交给美术动效深化。已有讲法清楚就继续，不强制所有段落先产出多个方案；不清楚时比较少量有实质差异的方向。

不能交接“做一个高级流程图”或只有栏目名称的空表。后续实现必须读取完整当前指令，不能压缩为一个组件名称。

### 5.2 美术：先让主体和关键画面成立

读取完整导演指令后，深化轮廓、比例、部件、连接、材料、观察距离、主次面积与排印。按实际运动需求拆分部件，标签和对象保留归属。

用真实文字、实际字体及本期材料，在模板正文区域制作关键状态。检查主体是否可辨、是否突出、留白是否有用途，以及是否仍主要靠长文字解释。关键状态数量由段落需要决定，不固定为几张。

主体像通用矩形、图标列表或界面卡片时，先修造型与构图，不靠光效、阴影和弹簧补救。文字是合法表现材料，但不能让正文的每种关系最终都变成文字条。

### 5.3 运动：连接状态，设计中途

明确谁发起、谁跟随、沿什么路径、哪些部件共同运动，旧重点怎样退让，新重点怎样获得位置。检查新旧对象同场、部件离位、遮罩显露、观察距离变化等风险时刻；危险中途不一定是时间的 50%。

动作时长先用范围安排，再结合实际音频、位移距离、阅读需求确定最终帧数。保留已有音画对应；同一含义可保持，动作可交叠，不要求全程不停。

关键变化的开始、到达或显露可以对应不同语义落点，不能把同步理解成每个词弹一个标签。只有句级边界时按句级精度设计，不按字数伪造词级时刻。不得增加静音、推迟口播或擅自删改确认文案来迁就装饰动画。

### 5.4 实现：让组件服务于演出

实现前根据设计选择现有能力。默认布局无法保留主要过程时，在本期工程调整或新增组件，不为了复用组件把演出退化成文字框。

模板提供 `visualExtensions` 时使用它；其他模板使用自身入口。组件由帧或明确时间求值，可重复预览；语义时间来自实际发言，注意镜内、章节和组件局部原点。

持续对象保留身份，部件和标签随主体运动。使用嵌入媒体时核对素材自身时间，避免窗口重排导致源视频重播。既有依赖能完成就直接使用，不默认增加 3D 引擎、字体系统或新素材服务。

### 5.5 预览：在真实栏目中判断

先检验最能暴露本期设计问题的连续段落，确认主要过程存在，再判断美术与运动。复杂变化应检查各自风险时刻，不用一段简单淡入代表整片。

独立动画看起来成立后，还要在模板完整画面中检查与该模板实际保留元素的主次关系；有些模板并没有人物或主题导航。能播放声画时查看连续片段；只能抽帧时补看风险时刻和相邻帧，结合实际语义边界核对并记录限制，不能声称已完整试听。

代表段中成立的视觉语言可以沿用，包括材质、线条、色彩职责和运动性格；其他内容仍重新构思，不能把代表段布局复制到全部章节。

## 6. 导演指令应当具体到什么程度

以下为原创示意，展示交接深度，不是要求本期或未来任务使用同一场景，也不是已渲染验证的作品。

> 本段让观众看见供给与市场之间的联系怎样被阻断，以及影响为什么会回到供给端。正文区域采用供给端、市场端及两者连接组成的示意画面；沿线移动的对象表达技术供给。标签辅助识别，不用三个大文字框代替主体。
>
> 入口保留完整连接，让观众先认清两端关系。讲到限制时，阻断发生在线路中间；阻断前后仍保留同一条线路，让观众能追踪变化。随后将注意转向市场端，表现连接失去覆盖，再揭示供给端的影响。没有数值依据时，不用几何比例暗示具体损失大小。
>
> 最容易混乱的是阻断出现、原有流动尚未结束的时刻。此时只突出阻断位置，两端保持稳定，不同时弹出结论和多条新连接。具体轮廓、线路走向、局部明暗和曲线由美术作者在实际模板中深化。
>
> 声画接点先引用对应原句，配音完成后校准。出口保留受影响的市场关系，接入下一段市场份额解释。先试作从正常连接到阻断后关系看清的连续范围。

这份指令仍需美术深化：不能把“供给端”和“市场端”再次做成两个通用文字矩形就交付。要让主体具有适合语境的可辨形态、空间关系与运动可能性。若这种讲法不适合正文区域或材料条件，应重选讲法，不机械套用示例。

图表、场景、原创示意、实物或文字表演都可以成为选择。不能为增加丰富度编造数据、历史曲线或未经验证的结构事实；也不强制所有抽象观点都套图表。

```markdown
只能取得静帧时记录观察限制，不声称完成连续播放或试听。
```

### 9.3 Worker Render 入口提示

Worker 先通过现有 `skills/list` 取得实际插件 Skill，确认插件身份、启用状态与安装路径，再在 `turn/start` 的输入中明确传入本阶段使用的 Skill。Analysis 只显式传入 video-pipeline；Render 显式传入制作、导演、美术三个 Skill。Remotion 和 FFmpeg 继续作为已安装技术能力按需使用。检查插件包含五个 Skill，不等于要求 Analysis 执行导演和美术工作。

这一步负责确保能力被正确接入；先读模板、再设计和预览的工作顺序仍由制作流程约定。提示词不硬编码插件缓存版本目录，不复制两份 Skill 全文。拟将 `prompts.ts` 中 `renderCreation` 精简为以下含义：

```text
读取本任务完整内容与已下载模板，按 video-pipeline 的制作流程执行。

保护项由该模板提供，不从其他模板继承，
使用真实配音校准动作；实际预览后按问题返回设计或实现修订，完成既有交付检查。
```

都保存在当前任务工作区，不是上游新增上传资料，也不是让用户填写设计问卷。

| 位置 | 保存内容 |

## 11. 开发顺序与验收

### 11.1 开发顺序

1. 在唯一源码目录新增两份 Skill，校验格式，确认全文与附录一致；整理制作流程与路由，替换重复旧指导。
2. 更新插件打包清单、运行清单和版本；修改实际 Skill 发现及分阶段输入逻辑，保持 Analysis 职责不变。
3. 按第 8.1 节整理财经模板边界与引用，独立递增模板版本并重新打包；确认没有修改模板动画源码与媒体素材。
4. 生成插件发布摘要和 Worker 运行版本，完成打包、加载、阶段输入及模板读取测试。插件包不包含模板 ZIP；模板包单独核对内容与摘要。
5. 按既有部署流程推送代码并在服务器拉取；确认没有活动制作任务后停止 Worker，保留匹配的旧版本和配置。用 Worker 服务用户、实际 Codex 和 Python 环境安装新版插件，不只执行 Git 拉取。
6. 执行 host-check，核对实际安装版本、五个插件 Skill、媒体依赖及隔离环境；按既有发布流程同步 API、回调与 Worker 版本，启动服务。安装或版本校验失败则处理部署问题，不静默退回读取仓库 Skill。
7. 网页上传新模板包，从“数据解读”正常创建新任务、选择该模板，完成 Analysis 和 Render。通过运行记录核对插件版本，通过本期制作资料、组件和实际视频核对执行效果。

若需要回退，应恢复相匹配的 Worker 代码、插件版本与配置，再做启动检查，不能只切换插件目录而保留不匹配的预期摘要。旧任务冻结模板不替换；复测旧组合时创建新任务并选择保留的旧模板版本。

### 11.2 技术验收

- 新插件包包含两份完整 Skill 及引用资料，安装副本与发布摘要一致；不误装模板或历史任务。
- Codex 实际发现并启用五个属于当前制作插件的 Skill。覆盖缺失、禁用、错误插件身份、错误路径、摘要不符等失败情况，沿用现有明确报错，不静默用旧源码兜底。
- 验证实际发送的阶段输入：Render 包含制作、导演、美术 Skill；Analysis 只显式传入制作 Skill。网页与独立 Render 入口行为一致。
- 沿用 `output/<runId>/plugin-runtime.json` 核对实际插件版本和安装来源；运行记录证明加载，设计资料、组件与预览才用于证明实际使用，不能只检查提示词出现了 Skill 名称。
- 动态模板正常下载、冻结和复用；引用路径正确解析，边界说明随包保存，不从通用 Skill 读取固定财经路径。
- 财经模板新包只变化约定说明与元数据；新任务读取新规则，旧任务冻结包不变。
- 另一模板没有头像/导航或允许全屏创作时，不被套用财经边界；旧模板未单列边界文件也能正常读取已有规则。
- 既有真实配音同步、成片审片与合片回归通过；片尾单独按第 11.4 节检查，不把当前结束语漏播算作通过。
- 不增加公共动画协议、强制字段或新的用户审批环节。

测试应验证可读性、隔离边界与实际行为，不仅断言提示词包含某个短语。

### 11.3 创作与视觉验收

先用相同文稿和模板复测，和用户指出的文字卡场景比较；再选不同内容及另一可用模板验证通用性，不只围绕黄仁勋案例编写设计。

先在完整模板内预览有代表性的连续段落，再批量导出。若画面仍主要靠文字依次出现来解释结构或过程，返回导演设计与组件实现；若主体已经成立但构图或运动差，针对美术或中途状态返修。使用已有预览和审片记录，不另建自动美感评分系统。发布报告分别给出“接入是否通过”和“效果是否通过”，不能用任务成功、读过 Skill 或写过设计说明代替成片评价。

| 问题 | 实际验收依据 |
| --- | --- |
| 是否形成具体导演决策 | 指令中能辨认主体、观察顺序、动作关系、危险中途和出口，不是空泛栏目 |
| 是否摆脱文字卡代替表达 | 图形、画面或材料承担关键变化；文字用于必要标注、引语和解释 |
| 是否美术成立 | 真实输出的轮廓、比例、构图、排印和明暗具有明确主次，与栏目统一 |
| 是否运动成立 | 对象身份可追踪，关键中途清楚，速度与收势符合表达，停留有用途 |
| 是否保持同步与模板 | 语义落点准确，该任务模板声明的保护项保持、可更新项正确更新；不以财经元素列表验收其他模板 |
| 是否真的完成返修 | 记录具体观察、修改和受影响范围，最终证据对应当前成片 |

这些是专业观察标准，不是代码自动评分条件。不能以新增组件数量、图表数量、颜色数量、每秒变化频率或外站访问次数代替效果评价。

### 11.4 固定结束语：独立待修与回归项

插件 1.0.1 测试中，正文结束后才进入片尾，但模板固定结束语“每天三分钟，拆解财报里的关键信号。”未生成。保留该事实，不把“没有提前进入片尾”等同于结束流程完整。

后续开发须沿模板读取、制作安排、音频清单、时间轴与合片结果定位遗漏位置，再在实际丢失处修复；本轮文档更新不预判根因，也不新增结束流程协议。导演、美术 Skill 的接入不替代这项修复。

对存在已确认固定结束语的模板，验收应同时核对：结束语进入配音并在实际成片中完整播出；期间保持正文最终画面；所有口播结束后完整播放片尾视频。对没有固定结束语的模板，不额外加稿。最终报告应单列该项结果；尚未修复时，不得宣称完整片尾回归通过。

## 12. 失败处理、成本和本轮边界

表达不清、主体不好看、参考不适合或素材无法支持原构思时，Render 在任务内调整讲法、材料或设计，继续制作；不直接报公共系统故障，也不默认交给用户完成设计。

主要过程缺失先补实现；已有过程但美术差就修美术。修改受影响的分镜和前后接口，未变音频与有效产物按现有规则复用。原有执行预算、取消、未知收费结果和公共工具故障处理保留，不增加无限重试。

代价主要是更完整的设计、关键状态试排、连续预览与必要返修；参考资料也会占用时间和上下文。通过保留单一方法来源、按问题读参考、复用已有文件和局部重渲控制成本。

本轮不重做渲染引擎、不加固定行业图标、不强制三维或发光风格。共享财经模板只更新边界说明和版本包，不重写其动画源码；不把每句变成一个新镜头，不要求每段不停运动。新 Skill 提供更具体的创作方法，最终观感仍以真实成片为准。

正文结束流程继续保留：正文解说和动效完成 → 保持正文最终画面播放已确认固定结束语 → 全部口播结束 → 完整播放片尾。没有固定结束语时省去保持阶段，不自行加稿。

````markdown
# 导演如何给美术与动画下达创作指令

## 范围

本 Skill 指导创作沟通，可独立使用，不依赖其他文档、案例库、制作软件或团队调度机制。输出是具体的导演指令及有依据的修订意见，不包含渲染工具或素材。单人创作也可用它区分导演决策与视觉实现。

根据任务范围使用：只优化一句指令，就解决这句的表达缺口；制作完整段落，才展开完整演出。用户明确锁定的文字、事实、风格和时长必须保持。普通创作选择自主完成，不把专业设计问题全部转交用户填写。

## 一、导演决定观看经历，作者深化美术与动作

导演先决定本段在全片中的作用、主要对象、发现顺序、情绪与前后关系。美术与动画作者继续设计轮廓、比例、材质、字形、构图、路径与速度，并可以提出更好的主要表现建议。不要先把每句文案塞进固定版式，再要求作者美化。

导演需要把关键画面讲到能被想象，但不必提前指定每个坐标与曲线。细节是否应由导演锁定，取决于它是否影响事实、主要表达、品牌要求或前后衔接。其余细节让原作者结合真实材料作专业判断。

一份好指令应让作者知道：这段值得看什么，观众先看见什么，后来发生什么，为什么这样安排，哪些关系必须保留，以及哪里还允许创作。准确的文字和有目的的视觉发展，比形容词数量更重要。

## 二、把抽象主题转成可见的事件

从内容中寻找能够被看见的行为、差异、空间、材料或状态。先写一段连续观看描述，再分镜。镜头单位来自观察需要，不必跟随旁白的每个句号。

让画面承担能由画面完成的工作：观众可以直接看出数量增加，就不必同时堆满近义标题；需要解释边界、原因或不容易看见的条件时，交给旁白或少量文字。人物反应、空间感受、材料欣赏和形式节奏同样可以成为目的，不要求每个动作都证明一个知识点。

已有表达清楚可行就继续深化。主要讲法不确定时，比较少量在主体、观看方式或动作关系上有实质差异的方向；换两套颜色不算两种讲法。

## 三、给美术的是具体观看方向

### 从对象与观察距离开始

说明主角是什么，观众离它多近，第一眼应该认出哪个轮廓或部位。近距离观察物件、置身真实环境、平面文字表演和结构拆解，会产生不同构图。先选适合本段的观看方式，再谈颜色。

描述主体如何占据画面：是完整外形成为主角，还是局部细节占满视野；辅助材料保持在哪里；进入下一发现时，哪些面积被让出。留白应服务方向、呼吸、运动或阅读。既不要求全画面填满，也不把居中小物件加大片空底当成默认风格。

### 把风格词翻译成可执行选择

“精致”“有力量”“轻松”“高级”可以表达目标，但还需要解释如何形成这种感受。

将感受目标落实到主体轮廓、比例、空间、材料、路径和收势，结合当前内容判断这些选择是否成立，不建立固定的风格对应公式。

给颜色分配职责：哪些属于对象本身，哪些分离背景，哪些突出当前变化。给字体分配用途：标题、对象标签、必要解释和字幕分别承担什么。具体字款、字幅与精确色值可由作者在实际画面中深化；用户已指定的视觉身份除外。

### 提出有价值的材料需求

需要真实材料时，描述所需动作、观察角度、可见细节、前后余量和声音用途，使材料需求能够支持后续动画。

未取得的素材标为待验证，不假设图片已抠像、部件能分离或视频拥有任意角度。素材回来后允许反过来改变分镜。设计中的主要关系如果靠不存在的材料才能成立，应补材或重选讲法。

## 四、给动画的是一次完整演出

### 写清入口、变化与出口

先交代前一段留下的对象、位置关系或疑问。然后描述本段由谁发起变化、观众注意如何转移、什么旧关系仍然保留，最后交代下一段从哪里接住。

### 把最容易混乱的中途说清

寻找新旧对象同时在场、部件离开原位、观察角度改变、文字开始显露的时刻。说明此时谁是主角，什么应该退让，哪些参照不能丢，哪里不能被挡住。

中途不等于机械地截取时间的50%。导演指出关键观看关系，作者深化路径、遮挡和具体姿态。若中途设计仍说不清，先做局部试排，不急着批量完成整片。

### 描述速度的感觉与动作目的

导演应说明动作的力度、速度变化、跟随关系及注意力交接目的。作者据此调节路径、加减速、延迟、惯性和收势，不给所有对象指定同一缓动。

允许动作交叠：旧主体让出空间时，新主体可以开始建立。是否同步或错开取决于表达；公正比较可以同时进行，逐个发现可以错开。不要把全程不停、每层弹跳或每镜变形当作丰富度。

真实切镜、稳定观看和动态延续都可成立。重要的是观众有没有清楚的观看理由，以及当前动作如何结束或被下一动作接住。

## 五、将声音和文字写进观看过程

提供准确的旁白、原声与必须上屏的文字，区分创作备注和画面文案。说明哪些内容观众必须读，哪些只需辨认，哪些由声音解释。不要把整段旁白同时变成大标题与标签。

先按语义安排声音与可见事件的先后关系。有真实音频后再校准时刻；初排秒数应标为估计，不能冒充实测词级时间。

阅读从文字达到有效大小、角度和对比时开始。高速移动中出现过文字，不等于已经完成阅读。声音落点可以对应开始、到达、显露或反应，不必每次运动都配音效。

已有声音并非天然不可改，是否锁定取决于用户要求。允许修改时，让讲述和画面相互调整；明确锁定时长或音轨时，先在约束内解决节奏。无法兼顾必要内容时说明冲突，不用无意义停留或悄悄删掉内容掩盖问题。

## 六、用参考校准选择，不复制外壳

实际查看参考后，指出具体借鉴点：主体的体量、文字与物体的关系、观察距离变化，或某次动作交接。说明它在当前内容中如何改变。未实际观看的动态只能作为待验证方向。

整片美术参考与局部动作参考可以不同，但需要在当前作品中形成一致选择。参考中的米白、黑底、纸片或设备不自动继承。也不要为了避免重复而机械改成另一套颜色；主体、空间与观看方式是否适合内容更重要。

当一系列新片总是出现同样的背景、大标题和容器时，检查导演是否在每次开始就预设了相同结构，是否只替换文案，以及是否把历史代表段当成默认模板。先改变不适用的主要构图与演出，再判断配色。

## 七、可直接采用的指令组织方式

以下是写作骨架，不是要求用户填写的问卷。导演应根据已有内容完成选择，简单任务可合并成一两段。

1. **本段作用：** 前文建立了什么，本段让观众产生什么认识或感受，下一段为何接入。
2. **主要画面：** 采用什么主体和材料，从什么距离观察，第一关注是什么。
3. **美术方向：** 主体轮廓与比例、空间关系、材料和色彩职责、文字用途；哪些交作者深化。
4. **连续演出：** 入口怎样成立，谁发起变化，旧重点如何退让，危险中途怎样保持清楚，出口留下什么。
5. **声画安排：** 准确文案、声音与可见事件的关系、大致动作及有效阅读范围。
6. **约束与试排：** 必须保持什么、允许改变什么、哪些材料尚未验证、先看哪个真实过程才能决定继续。

交出去的是一份有具体内容的连贯指令。不要用一长串栏目名代替创作，也不要在下游执行前又把完整指令压缩成“按上述风格做高级动画”。

## 八、导演怎样审方案和提修改意见

先判断本段是否值得这样表现，再判断美术和运动是否成立。没有技术错误不等于有吸引力，完整的文字论证也不等于已经形成好看的画面。

方案阶段看观看过程是否具体，关键材料能否支持；关键画面阶段看主体、字形、构图和材料；连续试排阶段看中途、速度、阅读和交接；放回整片后看声音与前后节奏。证据不足时明确未确认部分，不把静帧当连续观看。

修改意见采用“观察到的问题—原因判断—保留项—具体变化—复查范围”的顺序。原因不确定时提出要验证的假设，不冒称已经定位。

如果画面只在换字，回到主要事件；如果对象有变化但造型弱，修轮廓、比例与材料；如果关键画面好看但中途乱，修注意转移与遮挡；如果设计清楚而实现遗漏，补实现。不要把所有返修都写成加阴影、加弹性或节奏更快。

## 九、交接与收口

交付完整当前指令、准确画面文案、已确认材料与待核项、关键约束及需要查看的实际过程。材料或试排改变主要表现时，更新整份指令及相关前后段，不让作者同时面对互相冲突的旧新要求。

代表段通过实际观看后，沿用其中成立的视觉语言，并根据新内容重新构思。统一可以体现在材料、排印、色彩职责和运动性格，不意味着每段复用同一背景与布局。

导演采用表示当前方案值得继续实施；完成渲染表示已有输出；实际审阅才支持对当前观感的判断。最终结论如实说明已看过什么、仍有什么问题，以及交付物与审阅版本是否一致。
````

````markdown
# 动画生产与美术运动方法

## 使用范围与独立性

本 Skill 是独立的创作方法，必要的设计与执行要求均在本文中。它不依赖特定项目、案例库、插件、素材目录、字体目录或代理调度机制，可以由同一创作者执行，也可以用于团队协作。

它指导怎样设计和评价动画，不提供渲染引擎、字体、素材或工具接口。开始实现时，使用目标环境实际具备且允许使用的绘制、动画、音频和预览能力。目标环境支持标准 Skill 发现时，将本文件放入其技能目录的 `motion-design-production/SKILL.md`；其他环境可把全文作为创作指令加载。

任务范围决定工作深度。一个局部强调不必重做整片；用户已经确定的文案、素材、风格、时长和动作参数应被尊重。仅讨论设计时输出分析或方案，仅要求制作时才推进实现。缺少关键输入时说明缺口；可自行判断的普通设计细节直接完成。

## 一、从观看任务形成表达

先明确观众在这一段需要理解、发现、感受或记住什么，再决定让什么对象发生什么变化。把想法写成具体过程，说明对象身份、变化顺序与需要被看懂的关系，不用抽象风格词代替演出。

选择载体时一起考虑识别和运动可能性。需要展开的对象应有可辨认的内部；需要比较的对象应有共同尺度；需要揭示的内容应与原来被遮挡的位置建立关系。真实行为、人物反应、材料质感和纯粹的形式美感也可以成为观看目的，不要求每个动作都增加一条事实。

保留准确文字、数字、事实与对象身份。图形比喻可以简化外观，但不能用形变暗示不存在的因果，用大小或颜色暗示没有依据的优劣，或把原创示意当作真实证据。

现成画面已经清楚表达过程时，可以保持或直接剪辑；需要更清楚的关系、重点或情绪时，再安排动态图形。避免从名词直接跳到默认图标，也避免把每句旁白都变成一张独立卡片。

## 二、建立足够具体的输入

进入实现前，需要掌握准确内容、目标画幅、实际材料、声音条件、前后画面与硬约束。已有文稿不自动表示不能修改；用户明确锁定的内容则不得擅自改写、变速或裁切。

查看实际素材后再决定裁切、观察距离、文字位置和可分离部件。材料尚未取得时，可以提出待验证构思，但不能声称已经能跟踪、抠像或取得某个动作。普通素材不合适时继续寻找或调整表达；实际工具无法完成必要动作时，说明具体限制和替代方案的表达损失。

字体以目标环境可用的真实文件与字重为准，使用当前准确文案检查中文、标点、数字、缺字和换行。用户指定字款不可用时，说明差异并按目标项目的约定确认替代，不用静默回退伪装原字体。

## 三、美术：先把主体画成立

### 造型从轮廓、比例和行为开始

确定主体的识别轮廓、主要部件、比例、连接、开口与厚薄，再决定细节。观察它去掉纹理和光影以后是否仍能被认出。主体如果只是通用矩形，后加阴影通常无法补回缺失的造型。

绘制方法服务于形状。简单几何和规则文字可用矢量或布局工具；有机轮廓可用路径、插画或适用图片；需要真实空间转动时采用具备相应结构的模型或分层材料。不要为了全部程序绘制而把有价值的真实材料简化成低信息图标，也不要把一张平面图片当作已具备任意角度的三维对象。

按运动需要组织部件：文字属于票面，按钮属于设备，标签对应被指认对象。需要独立运动的部分才拆层，共同运动的部分建立共同归属。造型设计应让后续动作有依据，而不是画完后才决定能怎样动。

### 构图与排印一起决定

每个关键状态确定一个第一关注，并安排其他内容怎样支持它。主体的面积、位置、朝向、对比和周围留白共同决定重要性；第一关注不一定是最大文字。

使用实际最长文字设计字幅与分行。显示字承担性格，正文承担阅读，标签承担归属；字形、笔画重量、字距和行距应与画幅及观看尺寸相称。先处理内容组织、可用区域与合适字款，再考虑缩小文字。不要任意横向挤压字形，或用合成粗体冒称真实字重。

标题、字幕、标签、来源与画内文字可以各有作用，但不应同等显眼。普通字幕跟随语言，问题可以跨句保留，标签随对象移动，证据来源保留必要上下文。根据各自用途安排进入、保留与退出，不在每次换句时清空全场。

将画面缩到实际观看尺寸检查主次，必要时用灰度辅助查看明暗竞争，再回到彩色和动态复核。灰度检查不能替代色彩判断。

### 色彩、材质与空间形成一致关系

先决定画面的明暗结构、对象与背景的分离，以及想要的材料感，再分配颜色职责。强调色应帮助当前重点，而不是让所有对象同时突出。整片可以保持统一视觉语言，同时让不同段落拥有适合内容的构图。

物体风格需要一致的受光、合理的薄厚和接触关系。薄纸的边缘不应像厚设备；贴近表面和悬离表面的投影应体现不同距离。文字与边缘随物体运动，阴影根据物体、光源和承接面的关系更新。摄影已有光色时，让新增图形与其协调。

平面风格可通过轮廓、色块、排印、对齐和负空间成立，不强制添加三维、玻璃、发光或纹理。细节的作用是强化已经成立的造型与风格。

## 四、运动：把中途当作构图来设计

### 先确定关键状态

根据当前场面选择入口、主要发现、阅读或观察状态、风险中途和出口。数量由实际变化决定，不强制固定几张。每个状态明确主体、位置尺度、朝向、第一关注和仍需保留的参照。

概念草图用于比较构思；实际实现的画面用于确认真实字体、素材、排版和几何。不要用另一份理想效果图证明当前实现已经成立。

### 再连接状态之间的过程

逐对解释：谁先发起，谁跟随，哪个部件或整体运动，沿什么路径、绕什么轴心、改变哪些属性，下一动作在什么条件下开始。旧重点怎样退让，新重点怎样获得面积和对比，同一物体怎样保持可追踪身份，都需要具体安排。

中途是最容易发生遮挡、混乱或失去身份的状态，未必在时间的正中间。特别检查新旧对象共存、翻面最窄处、遮罩开始揭示、复制或合并、主体经过边缘以及替身接管的时刻。

当几个对象共同解释同一关系时，先设计它们的触发条件、归属与跟随关系，再分别调曲线，不给每层各写一条互不相关的进出场时间表。

### 速度来自动作目的和物体性格

用启动、加速、减速、跟随和收势形成轻重与力量。需要停下来读的对象在阅读位置收稳；需要果断出画的对象可以保留出画速度，避免在画面边缘慢慢停车。轻薄对象可以灵活，厚重对象可以克制，具体取决于风格与内容。

位移、旋转、缩放和显露不必共用一条曲线，只要共同到达需要的关键状态。反弹、错相、拖尾和预备动作按需要使用；不为“高级”给所有对象套同一弹簧，也不强制所有动作错开。

动作可以交叠：旧对象让出足够空间时，新对象就可以开始建立。交叠的判断依据是主次、可辨认性与内容落点。对称比较可以同步；逐个发现可以错开；明确切镜更清楚时就切镜，不要求所有边界都形变衔接。

## 五、声音、阅读和时长共同编排

先用秒级范围安排动作、阅读、观察与出口，再根据实际预览调整。实现需要帧数时，按目标帧率换算并处理取整，以当前内容和实际声音为依据确定时长。

声音和画面可以先听后看、先看后解释或共同落定。声音已经存在时，使用真实可核对的语义边界；只有句级时间就按句级精度安排，不按字数均分后声称取得了准确词级时间。

阅读时间从文字达到有效大小、姿态、对比和稳定程度时开始计算。文字已经进入画面但还在窄侧面翻转，并不等于观众已经能读。关键音效对应可见事件，音乐支持段落强弱，不必给每次运动都配音效。

停留可以服务于阅读、比较、反应、情绪或材料欣赏。内容完成后及时接续；不要用无意义漂浮、长尾缩放、冻结或整体放慢填满时间。必要定格和重放应有明确观察目的，真实事件的重放不能被误呈现成第二次发生。

没有硬时长时，通过预览决定合适长度；用户锁定时长时，在边界内调整编排与信息密度。若必要内容和限制无法兼顾，明确冲突并请求取舍，不擅自删改已锁定内容。

## 六、先写完整演出，再落实实现

对承担连续解释或重要视觉记忆的段落，在实现前形成一份连贯说明：内容与结尾目标，主体轮廓与部件，准确文字，构图和材料，连续对象关系，秒级动作及交叠，阅读条件，声音接点和前后接口。写当前具体决定，不只填写“风格、节奏、检查”等栏目名。

细节深度与任务相称。简单强调可用短说明；重要段落需要把容易误解的中途写清。局部坐标与曲线可在实现中修订，主要表达变化则与内容负责人或用户已有约定保持一致。

选择能够保留设计的工具或组件。组件默认布局和动画无法完成主要过程时，调整实现方式或明确限制，不让默认值悄悄改写设计。代码动画宜由明确时间或帧状态求值，保持可重复预览；关键帧工具则维护同样明确的时间、层级与属性关系。

持续对象保留身份和状态；附着部件使用正确局部关系。嵌入视频时分清源时间、段落时间和整体时间，同一来源的多个窗口需要时使用一致取帧时刻。窗口重排不应意外重播源视频。替身接管应核对内容、位置、尺度、朝向及源时刻，防止双影和跳位。

实现后先核对主要过程是否存在，再看效果。变量名、事件表、编译成功和渲染成功都不能证明观众看到了预期关系。缺失过程就补实现；过程存在但效果差，就修改设计。

## 七、预览、定位问题与修订

先看真实输出的关键状态，再连续观看完整段落与前后衔接，结合声音复核。独立动画成立以后，还需放进实际背景、字幕、人物或其他素材中检查主次与节奏。

| 观察到的问题 | 优先检查与修改 |
|---|---|
| 画面像表格或通用卡片 | 主体轮廓、部件比例、主次面积，是否被标题和说明挤小 |
| 配色整齐但没有重点 | 明暗层级、强调色职责、多个对象是否等权竞争 |
| 起终帧好看，中途拥挤 | 新旧对象共存时的位置、遮挡、投影面积与文字显露条件 |
| 动得顺但发飘 | 动作发起关系、位移和姿态速度、收势是否符合对象性格 |
| 看不懂对象从哪里来 | 身份连续、部件归属、出现位置和比较参照 |
| 文字读不清 | 实际字形与字幅、有效阅读起点、对比、遮挡和阅读时间 |
| 节奏拖沓 | 停留是否有用途、出画是否停车、动作间是否存在不必要等待 |
| 独立作品好看，合成后杂乱 | 背景、字幕、人物、音效与动效是否争抢同一关注 |
| 源视频跳位、重复或替身闪现 | 源时钟、局部坐标、接管时刻与重复图层 |

每次返修说明实际问题、判断原因、保留部分、具体修改和复查范围，避免仅说“更高级、更流畅”。

有时实现准确但构思本身平淡，需要回到表达；有时叙事成立但美术弱，应固定内容修造型和构图。区分问题所在，不把所有问题归为曲线，也不把所有视觉问题推给文稿。

静帧支持静态判断，源码支持实现核对，连续视频支持运动判断，实际声画播放支持节奏与听感判断。只能取得部分证据时，准确说明已看范围与未审部分，不宣称完整审阅通过。

## 八、参考、协作与交付

参考按当前问题选择：美术方向、造型、排印、观看关系或局部动作。实际查看后说明借鉴了什么、哪些条件不同、当前如何重新设计。没有适合参考也可以原创；不把参考对象、色板、剧情和秒数固化为全部任务的模板。

团队协作时，内容负责人确定主要表达与前后关系，视觉运动作者持续负责造型、构图、动作和实现，实际预览回到原作者修订。单人工作也保持这条反馈链。材料、文字或声音变化时检查受影响的构图、路径、阅读与出口，不只替换文件。

交付与任务相称的设计说明、可编辑源文件或工程、实际使用素材与字体说明、画幅和时长、预览或成片，以及尚未解决的问题。用明确版本对应说明与输出，避免旧说明配新动画。

结束前简要核对：主要表达已经实现；主体与文字可辨；风险中途清楚；声音与阅读匹配；前后衔接成立；交付版本与实际审阅版本一致。技术完成、专业观察和用户确认分别如实说明。
````
