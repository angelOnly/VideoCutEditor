## 这次只做了三件事

1. **把制作要求直接交给 Render。** 根据本期稿件设计画面，真实配音讲到相应内容时，让图形发生有解释作用的变化。要求落实到本期组件代码，不能只写设计说明。
2. **去掉互相冲突的模板要求。** 栏目要求保留的人物、字幕、导航等继续复用；正文可以直接编写本期图形，不必先填满基础组件再申请扩展。模板仍从当前任务下载，通用 Skill 不指定财经参考片或历史工程路径。
3. **要求实际查看并修改作品。** 先生成代表片段，查看关键状态和运动过程，对照原稿与实际配音检查。发现画面没回应讲解、时机不对、文字难看或布局有问题，就修改本期工程并复查，再批量导出；最终分镜仍须复查。

本次沿用已有时间轴、组件入口、预览工具和审片记录，没有增加公共动画事件协议、审查系统或 MCP。先前长方案中的新接口和新工具不纳入本轮开发。

## 实际运行顺序

任务选择模板 → 现有流程下载并冻结模板 → Analysis 确认文字 → Worker 将创作要求和任务入口交给 Render → Render 读取本期原稿、确认稿和当前模板 → 设计本期画面 → 取得真实配音时间 → 在任务工程编写图形和运动 → 用已有工具预览、查看、修改 → 批量导出并复查 → 原有交付入口合片和终检。

已确认的片尾顺序继续保留：正文完成 → 保持正文最终画面说固定结束语 → 全部口播结束 → 追加完整片尾。

更换模板后，Render 读取新任务的模板；正在执行的任务继续使用已经冻结的版本。替换网页模板不会自动改变旧任务的冻结包。

## 问题怎样处理，有什么代价

画面不好、参考不适合时，Render 调整本期设计并继续制作；不把普通设计修订直接报成任务故障。时间、字幕、媒体等技术错误沿用现有检查和修复流程。基础设施错误与运行预算仍沿用原有处理，不新增无限重试。

预览和修订会增加制作时间。当前要求依赖模型实际执行，无法靠提示词保证每条成片都达到参考片水平。只有看图能力时，检查实际视频的变化前、中、后和疑点相邻帧，并核对真实配音时间；不能声称已经完整观看或试听。
