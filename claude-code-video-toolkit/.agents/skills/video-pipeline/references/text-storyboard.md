# 共用文本分镜方法

读取完整原稿、完整要求、输出规格、模板身份与文字级栏目说明。保留事实、数字、引用、标点和原文顺序；按自然句组织口播，一句一项。不得把多句整段放进同一项，也不得按逗号机械拆碎；不追求固定分镜数。最多 200 项，每项非空且不超过 4000 字符。

本阶段只整理文本，不改写双人对话、不生成角色、画面意图、visualBlocks、关键词、字幕模式、素材时间或技术规划。原文非空标题也必须保留，不能擅自当非口播删掉。句间纯空白由程序记录。

Worker Analysis 最终只返回：

```json
{"status":"candidate","scenes":[{"text":"第一句完整口播。"},{"text":"第二句完整口播。"}],"error":null}
```

明确无法完成时返回 `status=failed`、`scenes=[]`，error 为 `{code,message,retryable}`。不要包 Markdown，不计算或生成 ID、摘要、源坐标和估时，不调用文件写入脚本或任何制作工具。

Worker 按 Unicode codepoint 顺序精确匹配原稿，生成 scene_001 等稳定 ID、源映射、空白记录和每秒 5 个非空白字符的展示估时；production={}、previews=[]。正文不匹配或 JSON 不合法即失败，不进入工程修复循环。展示估时不得成为 Render 制作时长。

本地完整任务同样先生成上述文本结果；外部确定性工具保存内部方案后，按已授权范围接续 production-flow。文本方法不因运行位置变化。
