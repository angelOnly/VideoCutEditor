# 共用视频制作流程

本地完整制作与 Worker Render 都执行本文件。读取可信任务、原输入、同一模板快照、确认文本和明确业务要求及本任务已有资料。Render 是本期最终创作阶段：先检查环境、字体和模板所需依赖，再调用收费服务；负责制作质量而不是只负责导出成功。不要照搬 Analysis 估算秒数，不删稿、使用未授权素材或改变交付镜头来适配时长。

### 输入检查与制作规划

先实际读取 request.input 指向的完整原稿、要求、素材和冻结模板，以及 confirmation 指向的本 run 确认列表。原稿用于理解语境，最终口播、ID、数量和顺序服从确认稿；文件缺失不能依赖聊天记忆补齐。确认文本中的估时仅供展示。

按 5a46746 的制作顺序保留完整能力：检查输入与依赖 → 制作规划 → 配音及实测 → 模板任务工程 → 实际时间轴 → 审片 → 导出 → 实片检查。Analysis 只抽走文字拆分；角色、章节、素材、图解、动画、字幕与节奏都在本阶段安排。结合当前稿件选图解，不照搬参考片正文。先规划全局章节和声音，再按确认 ID 导出 N 个 MP4。

### 模板自适应与质量反馈

章节数、图解项目数、文字长度、动画时长是默认推荐值；超出时读取具体位置，判断实际效果，必要时在任务副本调整布局、时序或组件，重验受影响静帧和动态片段。效果合格可保留超范围值；推荐提示不算失败，不因首次制作检查失败就结束任务。不要为了数量上限改确认列表、删字、截音或无限缩小字号。

复用栏目视觉骨架，允许在任务副本注册新图解的真实渲染组件及参数检查，禁止只增加名称或移除校验。有意叠层须明确标记并审查前中后画面；实际文字溢出、错误遮挡、动画未完成仍须修复。TASK_LAYOUT_INVALID 属当前工程问题，由 Render 调整后继续，不误判公共链路故障。

声音窗口与画面覆盖分开：合理多次延长没有累计一帧上限；保留 contentFrames、字幕和实际音频，不因补画面隐式延长 BGM。音效未指定长度时测量完整素材，显式剪辑须有编排依据。财经工程通过 derive-timeline 后给 render 传入对应 scene-XX-props.json，让可信检查能核对实际声音窗口与全局 BGM 起点。先稳定各镜混音边界，再渲染最终画面，避免后镜变化造成反复导出。

共享代码缺陷、授权、未知收费结果及预算边界仍按原规则处理，不允许无限重试。

### 配音

Codex 决定角色与发言顺序，调用通用配音工具；Worker 必须调用 video_tts，并将角色标签映射为服务器当前获准的实际音色；独立本地任务使用下面的 stage_tts.py。按确认文本准备任务内清单：

```json
[
  {"id": "utterance_001", "sceneId": "scene_001", "role": "host", "speaker": "实际已确认音色 ID", "text": "第一句。"}
]
```

同一镜可有多条发言，按顺序拼合必须等于该镜确认文本。财经双人模板默认每个自然短句对应独立 TTS 和一句字幕；已有有效音频优先复用。有可靠且绑定实际音频摘要的时间记录时，可按冻结模板 captionTiming 格式分页；禁止按字数或比例猜字幕时间，不为分页无条件重新收费。这个要求避免依赖中文逐词对齐；每个提交镜头都必须包含其完整口播。

```bash
python3 "$TOOLKIT_ROOT/tools/stage_tts.py" --request "$REQUEST" --script "$JOB_DIR/render/dialogue.json"
```

可信底层工具加载项目根 `.env`，不复制凭据。缓存按精确文本、实际音色、资源模型及生成格式匹配，成功音频还需校验摘要和解码。请求状态保存在 `cache/tts/<key>/request.json`，结果未知会返回 `EXTERNAL_RESULT_UNKNOWN`；不得删账本或另换 ID 来盲目重发。普通任务恢复只读本任务缓存。已有供应商之外的能力，仍需按部署授权使用，不自动购买新服务。

### 时间轴、工程与渲染

根据真实音频安排画面和字幕。TTS 成功后，使用音频清单和 `ffprobe` 读取每段音频的实际时长；同一镜的多段发言按确认顺序累加，得到实际起止帧。不得用 analysis 估算值或字数比例推算镜头总时长。当前协议不要求声学逐字或逐词时间戳，不检查或安装对齐工具；未配置对齐服务不得返回 `CAPABILITY_MISSING`。保留零时长、解码失败和音画总时长不一致等问题证据；没有实际试听时不得声称人耳验收。

正式 timeline.json 由 Render 根据实测配音、素材和制作意图编写，保留全局起止帧、音频来源及实际字幕数据。工具只检查或执行明确的编排，不重新决定章节、停顿或总时长。不得调用旧 resolve-timeline 覆盖工程时长。

在 project 创建当前模板的任务副本，按其结构适配正式时间轴。财经模板可使用 video_media 的 derive-timeline 做纯格式转换：timeline.json 必须明确 withBgm 布尔值；转换保留原记录、不打开被关闭的 BGM、不改时长。其他模板在自己的任务工程中适配，不使用财经转换器。

Worker 的 render、assemble 和可选适配操作使用 video_media；video_exec 用于任务工程、时间轴编写以及只读媒体测量。request、运行时和依赖由 Worker 固定注入，本机受控驱动调用相同 CLI。

返回 adjustment_required 不是产物成功。TIMELINE_EXTEND_REQUIRED 给出完整混音所需最小帧数：Render 调整本任务画面覆盖、后续全局偏移和相关工程；需要单纯尾部延长时可选 extend-timeline，它只按实测下限平移坐标，保留更长的已定编排，不改变声音与字幕。声音编排未变且摘要有效时用 fixedMix=true 复用完整混音；Render 可安排额外无声画面，工具保留原混音并补足静音。CONTENT_TIMELINE_REQUIRED 表示源音频窗口不足，依据实测重新编排当前工程，不运行另一套重算策略。

MIX_REBUILD_REQUIRED 表示全局 BGM 起点或声音编排改变，旧混音不再对应；保留旧记录，以 fixedMix=false 从有效源音频重新混音，不重复 TTS。混音摘要损坏属于 CACHE_CORRUPT，保留现场交人工核查。

所有镜头的最终声音边界尽量先确定，再统一渲染最终画面；后镜变化影响全片进度条或章节位置时，重做受影响画面。已通过但时间轴版本过期的镜头不算最终通过，有效配音继续复用。

字幕的样式、文字范围和分页服从模板。财经双人模板必须同时具有完整、可读的短句底部字幕和简短关键结论卡：结论卡不能替代字幕。每条句级字幕的起止时间取相应独立 TTS 的真实边界，不要求中文逐字或逐词对齐。`render/<runId>/timeline.json` 必须逐句记录 `id/text/src/startFrame/endFrameExclusive`，字幕默认以 `utteranceId` 一对一引用同一边界；可靠分页须同时提交 captionTiming 记录，保留原音频和确认全文。检查记录须引用工程实际使用的字幕数据及核对结果，不能只复制确认方案作为执行证据。

在 `project/` 创建独立正文工程。若冻结模板含 `renderer/renderer-manifest.json`，先读取清单，将 `renderer/` 复制到 `project/renderer/`，并将模板 `assets/` 复制到 `project/renderer/public/template-assets/assets/`，再实际导入并复用人物舞台、句级字幕、章节、音频和图解基线组件；不得只另写外观相似的临时页面。基线组件固定栏目语言，本期图解、数据、动画参数和专属场景由 Codex 围绕当前稿件创作。若清单声明 `sentenceAudioValidator`，可且只能通过 Node 执行该只读审计脚本；它读取确认方案、TTS 清单、时间轴和实际音频，失败时必须修复，不能跳过。工程的依赖可链接受信的 node_modules，业务资源复制进本任务；不得执行其他模板脚本、安装依赖或链接历史正文目录。

### 主控编排与章节并行

主 Render 先保存 `render/<runId>/direction.json` 和 `chapters/<chapterId>/brief.json`。编排绑定 `directionVersion`、确认稿摘要、有序分镜、实际音频摘要和逐句帧窗口；明确每章叙事目标、重点、入场／停留／退出、前后章衔接与可调整范围。视觉事件使用实际 utteranceId，不以字数比例推算词级时间。创作并发与渲染槽独立管理。

受控章节执行只能写自身 attempts 工作目录，提交绑定编排版本、brief 摘要、章节／尝试 ID 和真实文件摘要的候选；不能修改确认稿、全局时间轴、公共注册表或可信控制记录，不能调用收费配音。没有受控会话能力时由主 Render 按同一约定串行完成，明确记录限制，不把普通工具并发称为真实多代理验收。

主 Render 分三步验收：先审核视觉草案和重点冲突，再经共用媒体入口渲染并查看真实章节动态预览，最后合并已验收版本、复核跨章边界和整片节奏。预览由主控统一派发时，子代理提交预览请求与事件帧范围，不伪造预览路径。过期版本回复只能保留为历史证据。章节自己“通过”不能替代主控审查；截图检查不能替代动态检查。 首项需要等待后续句级锚点时，先保留上一组有意义的图解或显示当前段落主题卡；不能仅因事件帧列表合法，就接受长时间空白图解区。特别检查分镜中段、图解切换前后及片尾收束。

工程、时间轴、声音窗口和 props 稳定后，使用可信 `freeze-batch` 冻结清单，再 `render-batch` 调度分镜。同一冻结 bundle 共用，默认每槽帧并发 1；宿主与章节预览共用总槽位。批次执行期间不编辑正式输入，需要修复时先停止派发，重新生成版本和冻结清单。初版依赖变化保守失效，禁止只改摘要将旧画面登记为新版本。单镜失败保留其他有效结果，降低并发后重试仍须核对版本、文件摘要和剩余父预算。

渲染结果按确认顺序汇总，无论实际完成顺序如何。取消、租约失效和预算耗尽停止父任务全部子执行；不另起业务 run 绕过任务锁或预算。最终独立终检、口播保真、字幕和真实审片要求全部保留。性能记录分开创作、共享打包、渲染、混音、检查和整片墙钟；缓存命中不计为并行加速。

### 渲染前检查

先在当前 `render/<runId>/` 保存 `timeline.json` 和 `preflight-review.json`，再正式渲染。它们是本任务制作资料，不需要引入新的上游协议或固定布局 Schema：

- 从确认文本和明确业务要求提取本任务的硬性要求，逐项记录对应镜头、实现位置和检查证据。用户明确指定的角色/音色、文本、素材、组件复用要求必须保留；Analysis 不提供必须沿用的视觉段落；模板只用于补齐确认方案未限定的制作细节。
- 时间轴列出每镜实际总帧数、每段发言的音频来源和按实际时长计算的起止帧、模板要求的字幕分页及其起止帧、实际视觉段落的起止帧。区分口播长度与镜头总长度。财经双人模板在正式渲染前运行 `sentenceAudioValidator`，生成 `sentence-audio-audit.json`；该审计必须通过，且不以中文逐字或逐词对齐作为能力前提。要求“口播结束后出现”的段落应锚定口播结束，不能用“本镜倒数若干帧”覆盖尚未结束的口播。
- 必须复用的源码应从获准快照导入或复制后实际调用，记录原素材 ID 与工程位置；仅列入素材清单或另写外观相似的组件不算复用。
- 使用当前工程的 Remotion `renderStill` 等现有能力生成低成本关键帧，实际查看文字、人物、字幕和段落切换前后；在 `preflight-review.json` 记录看过的图片、帧号、检查结果及限制。技术依赖取 Worker 提供的 modules，不另找历史工程。静态图不能证明实际播放，音轨还须独立测量、解码并核对总时长。
- 正式渲染后还必须审查人物切换、章节进退、至少一组连续句级字幕、关键数据出现和片尾收束的动态片段；发现静态 PPT 式画面、字幕缺失或节奏不符时，修工程后重渲染受影响镜头。
- 若检查不通过，先修工程或时间轴；不得以“后续再调整”为由批量正式渲染。字幕显示效果、音频解码或音画总时长校验不通过时明确报告。

同一次技术恢复继续以确认文本和明确业务要求为准。旧失败工程可作本任务恢复材料，但不能覆盖确认要求；不得为绕过媒体错误改短已确认片头或改用其他组件。

通用 Remotion 执行器接受 Codex 选定的入口、Composition、props 和实测总帧数，PNG、单并发为当前保守默认。它不会生成图解、选择角色或重新切分分镜。

```bash
python3 "$TOOLKIT_ROOT/tools/stage_media.py" preflight --node /absolute/node \
  --modules /absolute/node_modules --browser /absolute/chrome

python3 "$TOOLKIT_ROOT/tools/stage_media.py" render --request "$REQUEST" \
  --scene scene_001 --project project --entry project/src/index.tsx \
  --composition Scene001 --props render/scene-001-props.json --frames 90 \
  --node /absolute/node --modules /absolute/node_modules --browser /absolute/chrome
```

这里 `--frames 90` 仅为示例，必须使用当前实际时间轴。指定的 Composition 规格/帧数不匹配会失败。执行器写临时视频，验证通过才替换成片，提供实际 MP4 的首中尾抽帧；必须调用图像工具真正查看它们及转场关键帧。浏览器关闭超时只回收自身进程组，非零退出不能直接当成成功。

执行器先保存无声画面和完整 PCM 混音，再统一编码 AAC 并封装 MP4，保留所有配音、音效和时间轴内的静音段。画面边界外的混音填充只有在全部声道浮点样本精确为零时才可归一化；不使用音量阈值，不覆盖原混音，任何非零尾音仍要求延长画面。返回的 `mix.path/sha256` 是实际混音，可用于清单中的 `audio`（另补确认全文）；不要用裸 TTS 替代混音。封装失败后，在工程/props/依赖未变时重试相同命令会复用原画面和混音，`renderReused: true` 表示没有重开浏览器。先阅读错误中的实际时长/偏移量；依据实测样本和制作意图调整画面覆盖，禁止截断有效声音或覆盖通用工具掩盖问题。硬预算耗尽必须停止，不能删除预算记录；正常补帧不属于修复预算耗尽。

最终编码损坏时检查原故障连续区间，不只看一张 PNG。根据模板处理片头/章节卡/片尾的内部时间；不存在通用的固定 16 镜或固定末尾静音裁剪量。必要字幕不可省略，必需旁白不可静音替代。无旁白的确认镜头可有静音音轨。

## 最终候选与确定性检查

保存 manifest，字段详见 Schema `$defs.manifest`。每个确认镜头必须返回：

- ID、完整确认文本、实际 MP4 相对路径、摘要、帧数和秒数。
- `usedResources`：实际源素材与生成资源列表，含 ID、类型、路径和摘要；实际源素材必须属于冻结授权集合，并包含客户端明确指定的 `assetRefs`；可以自行择用其他已授权素材，生成图解、音频不能假称来源素材。
- `resolvedVisualBlocks`：实际数值 `startFrame/endFrameExclusive`，连续覆盖本镜；不用计划表达式代替数值。
- `audio`：本镜完整混音源文件、摘要、完整文本。用于与编码后的声音比对，需包含内部静音、音效等，不能传未混音的裸 TTS 去比较混音成片。
- `captions`：原文字幕分页和实际起止秒数；无口播镜可为空。
- `evidence`：实际成片抽帧的帧号、路径和摘要，至少首中尾；渲染器返回这些字段。

同时写视觉审查 JSON（`$defs.review`）：任务/run/阶段/确认摘要，逐镜视频摘要、真实看过的帧号、检查结论、备注和局限。字幕是否确实烧录、画面是否符合模板须实际查看，JSON 字段不能自动证明审美合格。

`wholeVideo` 默认 `null`；请求要求整片时使用通用拼接入口（先准备全部分镜清单和视觉审查）：

```bash
python3 "$TOOLKIT_ROOT/tools/stage_media.py" assemble --request "$REQUEST" --manifest "$JOB_DIR/render/render_001/manifest.json"
```

拼接工具逐镜检查后保留视频编码，按本镜帧长归一化原始混音 PCM、拼接并只编码一次 AAC，写回 `wholeVideo`。整片不能占分镜列表第 0 项。所有  N 镜的音轨须全部包含，拼接后重新校验音视频时间戳、整片声音和边界。结果提供全部确认镜头，不只提供重做子集。

```bash
python3 "$TOOLKIT_ROOT/tools/two_stage.py" validate --request "$REQUEST" --artifact "$JOB_DIR/render/render_001/manifest.json"
```

通过后输出该 run 的 `result.json`。这是本地候选，不是 `delivered`、回调成功或服务端发布成功。失败返回明确阶段/错误码，保留此前合格产物。技术工具不自动证明所有业务描述已满足；Codex 的视觉审查与固定技术验证都要完成。


## 逐句交付与制作资料保存

一句确认口播对应一个 sceneId 和一个音画合成 MP4。N 句必须交付 N 个 MP4，不能让客户端再拼字幕、音频或多个视觉片段；句内可以切换多个图解与动画。统一设计整片工程，BGM 按全局偏移衔接，不能每句从头播放。片头归入首句、片尾归入末句，不新增无口播交付项。

在 `render/<runId>/timeline.json` 保存 `fps` 与有序 `scenes`。每镜 `id/startFrame/endFrameExclusive` 是全局帧区间，首镜从 0 开始，后镜连续接上前镜；每镜区间长度等于实际 MP4 帧数。镜内 `utterances/captions` 使用局部帧，均不能超出该镜帧数。utterance 含 `id/text/src/audioPath/startFrame/endFrameExclusive`：`src` 是工程 public 目录内路径，`audioPath` 是同一音频相对任务根的路径。财经模板 caption 含 `utteranceId/text/startFrame/endFrameExclusive`，边界和文本必须与对应句级音频一致；其他模板按自身字幕结构记录实际文字与区间。模板审计接收工程 public 路径；Worker 根据 audioPath 独立检查音频。

实际视觉、转场、BGM/SFX 的区间、工程入口、Composition、Props 及素材引用也记录到时间轴；它们描述本次效果，不禁止以后优化。manifest 的 captions 秒数必须等于局部字幕帧除以 fps。工程源码保存在 project，真实音频保存在 tool-audio 或任务内素材副本，保留全部相对依赖；node_modules 可链接可信锁定依赖，业务文件不能用外部符号链接代替。

候选 manifest 保存为 `render/<runId>/manifest.json`。Worker 技术终检后记录工程、时间轴、模板、音频和素材摘要到服务端 productionRecord；回调只投影文字和最终 MP4，不能因此删除制作资料。

## 失败、恢复与预算

同一版本的同一检查项成功后不重复检查；修改后重验受影响范围，全片最终一致性检查不能跳过。Analysis 估时不决定成片长度，不引入 ASR、中文逐字或逐词声学对齐。素材不足、输出规格冲突或缺少必需能力须保存证据并请求人工处理，不能静音、占位或改稿求成功。

制作工程故障先在任务内修复，按 Worker 可信反馈重验并继续。共享链路缺陷、收费结果未知、确认输入变化、缺少必需能力返回 human_required 并附具体证据；不能修改共享代码或自行重发收费请求。正常调整不扣普通修复次数，但计执行时间；预算耗尽、取消或连续无进展遵守可信执行层决定，不换 ID 或清账本绕过限制。正常恢复前确认旧进程已经停止；同 run 续跑只能恢复本任务资料。

本轮无法完成但仍有当前工程内可执行步骤时返回 continue_required，注明剩余步骤，不声称后台仍在渲染；需要人工的代码链路问题返回 human_required。candidate 必须对应全部镜头和必要整片的实际候选，Worker 会独立检查。人修复共享链路后，由管理入口批准版本并恢复，制作模型不得自行解除暂停。

后续优化须明确成功 run/resultVersion；受控恢复器先核对确认版本、模板和工具版本、文件摘要，再复制到新 run。旧工程和旧成片不覆盖；未改口播且音色一致才复用验证过的 TTS，时长变化重算后续全局偏移、字幕、转场和音乐。资料缺失报告不能恢复，不伪称已经恢复，也不自动从任意历史 run 取工程。
