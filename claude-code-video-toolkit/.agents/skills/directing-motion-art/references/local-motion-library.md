# 按需使用两类本地动效参考

## 一个入口，逐项读取

需要补充演法或借用实现时才使用本入口。导演与美术先说明当前画面、希望发生的变化、必须保持的对象和结束状态；按尚未解决的问题检索，不要求每段使用参考。

以本文件所在目录为基准，统一脚本是 `../../../../motion-reference-library/scripts/find.mjs`，路径相对于本文件，不相对于任务目录。服务器的 `$TOOLKIT_ROOT` 指向当前制作插件，可执行：

```bash
node "$TOOLKIT_ROOT/motion-reference-library/scripts/find.mjs" <动作或关系关键词>
node "$TOOLKIT_ROOT/motion-reference-library/scripts/find.mjs" <库名/案例编号>
```

关键词之间用空格分隔。检索默认返回三项文字候选，可用 `--limit 1` 至 `--limit 5` 调整；只想找带源码案例时加 `--kind source`，只想找动作拆解时加 `--kind mechanism`。精确编号直接使用候选返回的 `id`。

脚本内部读取清单完成检索，不会将全库内容交给模型。无查询只显示用法；精确查询只返回一项元数据和文件路径，不自动读取任何案例正文、图片、视频或源码。

不要先读取 `catalog.json`、全库索引、所有案例说明或整库图片来“熟悉资料”。先读候选摘要，再精确定位入围项、阅读其 `guide`，随后查看 `storyboard`；已有单张分镜且需要放大细节时才打开对应 `frames`。需要确认路径、速度、交叠、遮挡或衔接时才看对应视频。返回视频路径不代表已经看过运动。

## 两类参考采用方式不同

| 类型 | 返回标识 | 实际采用方式 |
| --- | --- | --- |
| 带源码案例 | `kind: source`，`hasSource: true` | 评估画面和运动后，按需读取 `files.source` 与必要 `dependencies`，将采用部分移入本期工程并改写 |
| 动作观察拆解 | `kind: mechanism`，`hasSource: false` | 根据说明和分镜理解对象关系与过程，必要时看原片；按本期内容编写实现，没有作者源码可复制 |

带源码不表示能自动容纳本期数据或保证效果；同族源码只采用需要的分支。动作拆解的原片是完整视频，不是已经裁好的本期片段，也不保证原片所需三维模型或素材在当前工程存在。

两类参考均可启发设计；也可以不用参考。不能因有代码就省略本期表达，不能为没有源码的案例虚构组件、依赖或精确时间。

## 导演与美术共同判断、组合

导演判断讲解目的、观看顺序和前后关系；美术判断主体、构图、运动可读性、真实材料与模板适配。双方可以提出保留、修改、部分采用或更换。同一个 Render 完成两个视角的判断，不新增代理或审批。

组合单位是本期完整演出，不是参考视频文件。可以只用一种参考，也可以从动作拆解借过程、从源码案例借局部实现。逐对补齐连接：前段留下哪个对象；后段从其何处开始；身份、位置、方向与参照是否延续；谁让位、谁接管；最后向下一段交出什么。不能把两个默认入场动画顺次播放，当作已经完成连接。

将采用结果融入现有章节 brief 的连续演出正文：精确编号、采用部分、本期改造、新增连接、准确画面文字、声音接点及需要预览的中途。美术与实现使用这份完整设计，不能再次压缩成案例名称；修改主要表现时更新同一份稿，不建立重复选型表。

## 本期实现与预览

实际创作边界从本任务下载模板读取。案例的背景、主体、字号、配色与全屏运镜不自动继承；已有参考代码与本期新增代码都写入任务工程，不修改共享库或模板固定层。

按真实配音安排各段动作的开始、到达、强调和阅读。参考的秒数不作为本期时长，不把短案例整体放慢、循环或冻结来填满长口播；后续讲解需要新的发现时继续设计过程。只有句级时间证据时，不假称已有词级对齐。

先看本期关键画面，再检查带声音和前后段的连续预览：既检查参考动作是否实现，也判断连接、停留和完整观看过程是否成立。检索命中、源码存在或渲染成功不等于效果通过。

## 没有结果或材料不完整

无匹配时可拆分运动阶段、改用动作关键词或另一种参考；仍不适合就继续自主设计，不为使用库硬套案例。不要用一次无结果作为全量读取的理由。

精确查询中的 `missing` 列出实际缺失文件；清单不可用时 `warnings` 提示对应库。没有读到的资料不能称已参考，可使用完好项或调整设计继续制作。查询参数错误应修正后重试；插件整体完整性仍由现有发布校验负责，不绕过校验。

## 何时主动寻找参考

演出只有抽象动作词、多个段落反复使用同一文字容器、转场缺少对象承接时，应先用当前表达问题检索少量文字候选，再与美术看候选图片；运动机理仍不清楚才看对应视频。不要遍历全库。无合适结果则自行设计，不能因此停工，也不以检索次数作为质量指标。

共同选中后，源码类才读取相关实现及依赖；机制类依据拆解独立实现。章节 brief 只记录借用的过程、本期修改与衔接，不复制整份案例说明。
