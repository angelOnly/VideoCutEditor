# 按需使用本地动效参考库

## 定位参考库

以当前加载的本文件所在目录为基准，`../../../../motion-reference-library/typemotion-tables/` 是同一插件内的参考库。该路径相对于本文件，不相对于任务工作目录。以下命令在解析得到的库目录运行。

不写死个人电脑路径、服务器版本目录或定制模板名称。库未安装或某个案例不适用时继续原有设计，不宣称已查看不存在的材料，不因此停止 Render。

## 先文字检索，再看候选图

先明确当前需要表达的动作与关系，再运行 `node scripts/find.mjs <动作或关系关键词>`；已知编号时直接精确查询。无 Node 环境时读取轻量 `INDEX.md`，不为查询另建服务。

检索最多返回五个候选。先阅读摘要，必要时读取候选 README 判断适用条件；不要先遍历全库图片或视频。候选说明记录现有动作，不保证它能原样适配本期数据。

查看筛选后候选的 storyboard.jpg。图片中的标签或连线不清楚时，再查看指定单张分镜。只有需要确认路径、速度、缓动、遮挡或交接细节时，才查看该案例视频的相关部分。图片支持构图和状态判断，不能据此声称已确认连续运动。

## 导演与美术共同判断

导演判断内容表达、发现顺序、声音关系和前后衔接；美术判断主体造型、布局、运动可读性及模板适配条件。双方都可提出保留、修改、部分采用或更换。必要时查阅局部源码或试排，解决影响采用的具体疑问。

同一个 Render 结合两个 Skill 完成上述判断，不增加子代理或额外审批。美术沿用已有候选，不重复从头检索；候选不适合时再扩大查找。库内没有合适表现时继续原创或按任务需要寻找其他参考。

## 将采用结果写回本期设计

在已有制作说明中交代：采用案例及具体部分、本期对象与关系、保留和改变的动作、关键中途、准确口播接点、前后接口。这些内容应构成具体演出，不是只填写栏目名称。只保留一份当前有效设计，修改后同步更新相关段落。

## 源码按需读取和改写

精确查询案例编号，取得说明、分镜、入口与依赖路径。只读取采用部分需要的源码，不递归读取其他案例。

将所需实现移入本期工程，替换示例内容并适配当前模板。同族源码含多个分支时，只保留采用部分需要的逻辑。`bare` 只关闭样片包装，不会自动重排；需要按模板实际创作区重新布局。本期改动不回写共享参考库或模板固定层。

## 用本期材料验证

以真实数据、实际标签和配音安排动作；重复短语结合所在句确定具体出现位置。明确声音接点对应动作开始、到达还是强调，不能用估计时间冒充实测时间。标签在需要识别对象时应已可读。

不沿用参考视频长度，不拉长短动画填满章节。先检查本期关键画面，再播放实际连续片段，复核中途、标签阅读、声音接点和前后衔接。问题属于设计时修改设计，属于实现时修正实现。
